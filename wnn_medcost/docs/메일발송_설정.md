## 2. 어디를 고치나

**코드는 고칠 게 없다.** `MailUtil`은 네이버·구글을 가리지 않는다 —
바뀌는 것은 설정값 `host` · `port` · `ssl` 뿐이다.

| 파일 | git | 용도 |
|---|---|---|
| `src/main/resources/mail.properties` | **제외**(.gitignore) | 실제 값. 로컬 개발용 |
| `src/main/resources/mail.properties.sample` | 포함 | 양식. **실제 비밀번호 절대 금지** |
| `/home/winner/conf/mail.properties` | — | 운영 서버. 톰캣 옵션으로 가리킨다 |

운영은 WAR 안 값이 아니라 서버 파일을 읽는다:

```
setenv.sh 의 JAVA_OPTS 에
  -Dwnn.mail.config=/home/winner/conf/mail.properties
chmod 600 으로 다른 계정이 못 읽게 → 톰캣 재기동
```

이 파일이 있으면 WAR 안 `mail.properties`는 무시된다.
**로컬만 바꾸고 끝내면 운영은 그대로 구글로 나간다.**

## 3. 네이버 전환 절차 — 순서가 중요하다

앞 단계를 건너뛰면 다음 단계 메뉴가 <아예 안 보인다>. 그래서 헤맸다.

### (1) 메일에서 SMTP 열기
네이버 메일 > 환경설정 > **POP3/IMAP 설정**
→ **POP3/SMTP 설정** 탭과 **IMAP/SMTP 설정** 탭 <둘 다> [사용함] > 확인

### (2) 2단계 인증 켜기
네이버 **내정보 > 보안설정 > 기본보안설정 > 2단계 인증 [관리]**

- 메일 환경설정 안에는 없다. **네이버 ID(계정) 쪽**이다.
- 보안설정 첫 화면에 뜨는 **패스키 관리는 다른 기능**이다 — SMTP에 못 쓴다.

### (3) 애플리케이션 비밀번호 생성
**2단계 인증 [관리] 화면 <안에>** 있다. 보안설정 목록에 별도 카드로 안 보인다.

- 용도 : 메일(POP3·SMTP)
- 값은 **한 번만 표시**된다. 잃어버리면 폐기하고 새로 발급.

### (4) 설정값 넣기

```properties
mail.smtp.host=smtp.naver.com
mail.smtp.port=465
mail.smtp.ssl=true

mail.smtp.user=hyun_otech          # ★아이디만. @naver.com 붙이면 인증 막힘
mail.smtp.password=<앱 비밀번호>    # ★로그인 비밀번호 아님
mail.from=hyun_otech@naver.com
```

## 4. 구글(백업) — 되살리기 전에 할 일

`mail.properties`에 구글 설정이 주석으로 남아 있다. 되돌리려면 네이버 블록을 주석 처리하고
구글 블록의 `#`을 지우면 된다. 단 **그 전에** :

> **★기존 앱 비밀번호는 폐기하고 새로 발급해야 한다.**
> `mail.properties.sample`이 git에 커밋되면서 같은 값이 GitHub `thyunoh/winn`에 올라갔다.
> (2026-08-07 발견 · 커밋 `add242c`, `0c99f13`)
> 그래서 주석에서 비밀번호만 빼고 경고를 달아 뒀다.

구글 주의사항 : **587은 반드시 `ssl=false`** — true면 접속 자체가 실패한다(2026-07-30 실제 발생).

## 5. 문제가 생기면

### `535 5.7.1 Username and Password not accepted`
연결·SSL·포트는 정상이고 **자격증명만 거절**된 것이다. 원인은 셋뿐이다.

1. IMAP/SMTP 사용이 꺼져 있음 → 3장 (1)
2. **로그인 비밀번호를 넣었음** → 네이버는 외부 프로그램에 로그인 비밀번호를 안 받는다. 3장 (3)
3. 아이디에 `@naver.com`을 붙였음 → 아이디만

아이디 형식·포트를 바꿔도 똑같이 535라면 **계정 설정 문제**다. 조합을 더 시도할 필요 없다.

### 보내는 사람 이름이 `ì...` 로 깨짐
`MailUtil.config()`는 반드시 UTF-8 Reader로 읽어야 한다.
`Properties.load(InputStream)`은 ISO-8859-1 고정이라 `mail.fromName`의 한글이 깨진다(2026-07-30 발생, 수정 완료).

### 발송을 안 하고 안내만 뜸
`mail.enabled=false` 이거나 `host`·`user`·`from` 중 빈 값이 있다 → `MailUtil.isReady()` / `notReadyReason()`.

## 6. 보내지 않고 확인하는 법

`Transport.connect()`는 인증까지만 하고 메일을 보내지 않는다. 계정을 바꾼 뒤 이걸로 먼저 확인한다.

```
jjs -cp <javax.mail.jar> 스크립트
  → mail.properties 를 읽어 connect() 만 시도
```

성공하면 **접속·인증까지** 보장된다. 다만 **실제 발송은 별개**다
(수신자 제한·스팸 정책 등). 계정 전환 후에는 본인 앞으로 한 통 보내 최종 확인할 것.
