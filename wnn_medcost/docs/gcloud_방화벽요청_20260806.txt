2. 대상 서버 선택
   - 인스턴스 ID : g-118109955450505754
   - 공인 IP     : 114.108.153.178
   - 사설 IP     : 10.26.170.2
   - 호스트명    : gcloud-seoul-10bf88ae80e2ffc2fffac7bf4c74b85f
3. [방화벽] 또는 [보안그룹] 메뉴로 이동
4. "아웃바운드(Outbound)" 규칙을 확인

   ▶ 아웃바운드가 특정 대역/포트만 허용으로 되어 있는 경우
      → 규칙 추가 : 프로토콜 TCP / 포트 443 / 대상 0.0.0.0/0 (허용)
      → 저장 후 [2단계]로 확인 (보통 재부팅 없이 즉시 반영)

   ▶ 아웃바운드가 이미 전체 허용(0.0.0.0/0)인 경우
      → 콘솔에서 해결 불가. [3단계] 기술지원 문의로 진행


[2단계] 적용 후 서버에서 확인 (SSH 접속하여 실행)

   curl -s -o /dev/null -w "%{http_code}\n" --max-time 8 https://generativelanguage.googleapis.com/v1beta/models

   결과 403 → 정상 개통 (구글까지 도달, 키 없이 요청해서 거부된 것)
   결과 000 → 아직 차단 중


[3단계] 가비아 기술지원 문의 내용 (콘솔에서 해결 안 될 때)

[요청 사항]
서버에서 외부로 나가는 통신 중 아래 대상이 차단되어 있어 해제를 요청드립니다.
- 대상 : generativelanguage.googleapis.com (구글 API)
- 포트 : 443/TCP
- 방향 : 서버 → 외부 단방향 (인바운드 신규 개방 없음)
- 용도 : 자사 서비스에서 구글 Gemini API 호출

[확인한 내용] (2026-08-06)
1. generativelanguage.googleapis.com, www.google.com, cloudflare.com
   → 80, 443 모두 무응답 (curl 응답코드 000)
   → curl -4 옵션으로 IPv4 강제해도 동일
2. github.com 200, www.naver.com 200
   → 해외 포함 일반 인터넷 통신은 정상
3. 서버 내부 방화벽 없음
   → iptables -L OUTPUT : policy ACCEPT, 등록된 규칙 없음
   → ufw : 비활성 상태

위와 같이 서버 자체 설정 문제는 아닌 것으로 확인되며,
구글 및 클라우드플레어 대역만 선별적으로 차단된 것으로 보입니다.
해제 가능 여부와 방법을 안내해 주시기 바랍니다.

[개통 후 할 일] — 위너넷 개발 담당

1. /usr/share/tomcat9/bin/setenv.sh 에 한 줄 추가

     export GEMINI_API_KEY="AQ.로 시작하는 구글 API 키"

   ※ 키는 소스·설정파일에 넣지 않는다(평문 금지). 환경변수로만 주입.
   ※ chmod 600 /usr/share/tomcat9/bin/setenv.sh 권장

2. 톰캣 재기동

     systemctl restart tomcat9

3. 전달 확인

     tr '\0' '\n' < /proc/$(pgrep -f catalina | head -1)/environ | grep GEMINI

4. 화면 확인
   적정성평가 Q&A 에서 등록 자료에 없는 말로 검색
   예) "소변줄 오래 꽂고 있으면 점수 깎이나요"
   → 주황색 [AI 참고답변] 배지가 뜨면 정상
   → 안 뜨면 logs/catalina.out 의 [QNA-AI] 줄 확인

※ WAR 재배포는 필요 없음 — 코드는 이미 배포본에 포함돼 있고,
   키가 없으면 종전 안내문구로 폴백하도록 만들어 두었음.
