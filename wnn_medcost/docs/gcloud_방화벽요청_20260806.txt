4. "아웃바운드(Outbound)" 규칙을 확인

   ▶ 아웃바운드가 특정 대역/포트만 허용으로 되어 있는 경우

      → 저장 후 [2단계]로 확인 (보통 재부팅 없이 즉시 반영)

   ▶ 아웃바운드가 이미 전체 허용(0.0.0.0/0)인 경우
      → 콘솔에서 해결 불가. [3단계] 기술지원 문의로 진행


[2단계] 적용 후 서버에서 확인 (SSH 접속하여 실행)

   curl -s -o /dev/null -w "%{http_code}\n" --max-time 8 https://generativelanguage.googleapis.com/v1beta/models

   결과 403 → 정상 개통 (구글까지 도달, 키 없이 요청해서 거부된 것)
   결과 000 → 아직 차단 중

[증상]
자사 서비스에서 고객사로 월간보고서를 메일 발송하는 기능이 동작하지 않습니다.
확인 결과 서버에서 구글 대역으로 나가는 통신이 전부 차단되어 있습니다.
(발송에 Gmail SMTP 를 사용 중이며, 이전에는 정상 발송되던 기능입니다.)

[요청 사항]
서버 → 외부 아웃바운드 허용 (단방향. 인바운드 신규 개방 없음)
 1) smtp.gmail.com        587/TCP   ← 메일 발송 (현재 장애, 최우선)
 2) generativelanguage.googleapis.com  443/TCP   ← 구글 API 호출

[확인한 내용] (2026-08-06)
1. smtp.gmail.com 587
   → openssl s_client -4 -starttls smtp 12초 동안 무응답 (연결 자체가 안 됨)
2. generativelanguage.googleapis.com, www.google.com, cloudflare.com
   → 80, 443 모두 무응답 (curl 응답코드 000)
   → curl -4 옵션으로 IPv4 강제해도 동일
3. github.com 200, www.naver.com 200, smtp.naver.com 465 연결 성공
   → 해외 포함 일반 인터넷 통신은 정상. 구글 대역만 안 됨
4. 서버 내부 방화벽 없음
   → iptables -L OUTPUT : policy ACCEPT, 등록된 규칙 없음
   → ufw : 비활성 상태
5. 콘솔의 방화벽(보안그룹) 아웃바운드 규칙은 전체 허용(0.0.0.0/0) 확인
   ※ 이 문장이 없으면 "콘솔에서 설정하세요"로 1차 답변이 오기 쉽습니다

위와 같이 서버 자체 설정 문제는 아닌 것으로 확인되며,
구글 및 클라우드플레어 대역만 선별적으로 차단된 것으로 보입니다.
해제 가능 여부와 방법을 안내해 주시기 바랍니다.


[재문의용] "차단한 적 없다"는 답변이 올 경우, 아래 결과를 붙여 회신

   traceroute -n -T -p 443 -m 15 172.217.115.4
   traceroute -n -T -p 587 -m 15 smtp.gmail.com

   어느 구간(홉)에서 끊기는지 보여주면 상대도 확인이 빨라집니다.

[임시 우회안 — 채택하지 않음]

네이버 SMTP(smtp.naver.com:465)는 연결이 정상 확인되어, 전환하면 방화벽을
기다리지 않고 메일을 즉시 되살릴 수 있었습니다.
2026-08-06 사용자 판단으로 [구글 유지]를 선택하여 전환하지 않았습니다.
→ 방화벽이 열릴 때까지 메일 발송은 중단 상태가 이어집니다.

되살려야 할 상황이 생기면 아래 3줄만 바꾸면 됩니다(재배포 불필요).
   mail.smtp.host=smtp.naver.com
   mail.smtp.port=465
   mail.smtp.ssl=true
   ※ 계정/비밀번호도 네이버 것으로. mail.smtp.user 는 아이디만(주소 아님).
   ※ 네이버 메일 > 환경설정 > POP3/IMAP 설정에서 'IMAP/SMTP 사용함' 필요.
   ※ 설정 파일을 서버로 빼려면 setenv.sh 에
      export JAVA_OPTS="$JAVA_OPTS -Dwnn.mail.config=/home/winner/conf/mail.properties"

[개통 후 할 일] — 위너넷 개발 담당

1. /usr/share/tomcat9/bin/setenv.sh 에 한 줄 추가

     export GEMINI_API_KEY="AQ.로 시작하는 구글 API 키"

   ※ 키는 소스·설정파일에 넣지 않는다(평문 금지). 환경변수로만 주입.
   ※ chmod 600 /usr/share/tomcat9/bin/setenv.sh 권장

2. 톰캣 재기동

     systemctl restart tomcat9

3. 전달 확인

     tr '\0' '\n' < /proc/$(pgrep -f catalina | head -1)/environ | grep GEMINI

4. 화면 확인
   적정성평가 Q&A 에서 등록 자료에 없는 말로 검색
   예) "소변줄 오래 꽂고 있으면 점수 깎이나요"
   → 주황색 [AI 참고답변] 배지가 뜨면 정상
   → 안 뜨면 logs/catalina.out 의 [QNA-AI] 줄 확인

※ WAR 재배포는 필요 없음 — 코드는 이미 배포본에 포함돼 있고,
   키가 없으면 종전 안내문구로 폴백하도록 만들어 두었음.
