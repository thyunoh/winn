## 1. 무엇을 고쳤나 → 무엇을 해야 하나

| 고친 것 | WAR 재빌드 | 톰캣 재기동 | 비고 |
|---|:--:|:--:|---|
| **JSP만** (`*.jsp`, `tiles/`) | ✕ | ✕ | 파일만 덮어쓰면 **즉시 반영**(톰캣이 다시 컴파일) |
| **정적파일** (`asset/`, `css/`, `js/`, 이미지) | ✕ | ✕ | 파일 교체 + 브라우저 캐시 비우기(Ctrl+F5) |
| **자바** (`*.java`) | ○ | ○ | 클래스는 리로드가 안 된다 |
| **매퍼 XML** (`sqlmap/mapper/*.xml`) | ○ | ○ | MyBatis 가 **기동 시 한 번** 읽는다 |
| **설정** (`spring/*.xml`, `web.xml`) | ○ | ○ | |
| **DB** (테이블·프로시저·마스터값) | ✕ | ✕ | DB 에 적용하면 그 순간부터 적용 |

> 정리: **JSP만 고쳤으면 파일 교체로 끝.** 자바·XML 이 하나라도 섞이면 WAR 재빌드 + 재기동.

## 2. 내 PC에서 WAR 만들기

```bash
cd C:/Users/HYUN/git/winn/wnn_medcost
D:/egv/apache-maven-3.8.4/bin/mvn.cmd -o clean package -DskipTests
```

- `-o` = 오프라인(로컬 저장소만 사용). 네트워크가 느려도 빌드가 멈추지 않는다.
- 산출물 : `target/wnn_medcost-1.0.0.war` (약 98MB)
- **빌드가 끝나면 내가 고친 파일이 실제로 들어갔는지 확인한다** (PowerShell):

```powershell
Add-Type -AssemblyName System.IO.Compression.FileSystem
$z=[System.IO.Compression.ZipFile]::OpenRead((Resolve-Path "target\wnn_medcost-1.0.0.war"))
$z.Entries | Where-Object { $_.FullName -like "*qps*" } |
  Select-Object FullName, @{n='KB';e={[math]::Round($_.Length/1KB,1)}}, LastWriteTime
$z.Dispose()
```

날짜가 **오늘 것이 아니면 빌드가 옛 파일을 담은 것**이다 — `clean` 을 빼먹었거나 다른 폴더를 보고 있다.

### 3.1 ★어느 앱을 고쳐야 하는가 (가장 많이 틀리는 곳)

`webapps` 에 **같은 앱이 두 벌** 있다. `ROOT` 와 `wnn_medcost-1.0.0`.

/usr/share/tomcat9/webapps/wnn_medcost-1.0.0/   ← ★실제 서비스는 이쪽
```

**반드시 `wnn_medcost-1.0.0` 을 고친다.** (2026-08-07 에 ROOT 만 고치고 한참 헛돌았다)

### 3.2 JSP 한두 개만 바꿀 때

해당 파일만 같은 경로에 덮어쓴다. 재기동 불필요.

```

```

### 3.3 WAR 통째로 바꿀 때

업로드 전에 **되돌릴 수 있게 지금 것을 백업**한다.

```

## 4. 재기동

### ★`systemctl restart tomcat9` 를 쓰지 말 것

톰캣이 두 개 떠 있고, 실사용 인스턴스는 **`catalina.base=/usr/share/tomcat9`** 쪽이다(443·8080 보유, root 실행).
`/var/lib/tomcat9` 는 빈 ROOT 만 있는 유령이라 systemctl 이 엉뚱한 걸 건드린다.

```bash
/usr/share/tomcat9/bin/shutdown.sh
sleep 5
ps -ef | grep -c "[c]atalina"     # 0 이 될 때까지 기다린다(안 죽으면 kill)
/usr/share/tomcat9/bin/startup.sh
```

기동 로그:

```bash
tail -f /usr/share/tomcat9/logs/catalina.out
```

> 참고 — `docs/메일_네이버전환_절차.txt`(2026-08-06) 에는 `systemctl restart tomcat9` 로 적혀 있는데,
> **그 뒤(2026-08-07)에 인스턴스가 둘이라는 걸 발견**했다. 위의 shutdown/startup 방식이 맞다.

## 5. 반영됐는지 확인

1. **화면**: 고친 화면을 열어 Ctrl+F5.
2. **클래스가 실제로 바뀌었는지**: QPS 는 컨트롤러가 응답에 `build` 표식을 실어 준다.
   개발자도구 → Network → `/qps/*.do` 응답의 `build` 값이 올라갔는지 본다.
   *(코드는 고쳤는데 화면은 그대로인 상태로 헤매는 것을 막으려고 넣은 장치다)*
3. **오류 로그**:

```bash
grep -iE "ERROR|Exception" /usr/share/tomcat9/logs/catalina.out | tail -30
```

## 6. 되돌리기(롤백)

```bash
/usr/share/tomcat9/bin/shutdown.sh
cd /usr/share/tomcat9/webapps
rm -rf wnn_medcost-1.0.0
mv wnn_medcost-1.0.0.bak_20260809_1013 wnn_medcost-1.0.0   # 3.3 에서 만든 백업
/usr/share/tomcat9/bin/startup.sh
```

**DB 변경은 롤백되지 않는다.** 컬럼 추가·마스터 값 변경은 되돌릴 SQL 을 미리 적어 두거나,
지장 없는 방향(컬럼 추가는 옛 코드에 무해)으로만 적용한다.

## 7. 함정 모음 (실제로 겪은 것만)

- **`webapps` 에 앱이 두 벌** — 실서비스는 `wnn_medcost-1.0.0`. ROOT 만 고치면 변화 없음.
- **`systemctl restart tomcat9`** — 유령 인스턴스를 건드린다. `bin/shutdown.sh`+`startup.sh` 사용.
- **`setenv.sh` 에 `>>` 로 옵션 추가 금지** — 파일 끝에 개행이 없어 앞줄에 그대로 붙는다.
  실제로 `-Dspring.profiles.active=prod` 가 `prodJAVA_OPTS=-Xms1024m` 이 되어 **prod 프로파일이 깨진 채 기동**됐다.
  편집 전 `cat -A` 로 줄 끝(`$`)을 확인할 것.
- **서버는 아웃바운드 HTTPS 차단** — maven 저장소에서 jar 를 못 받는다. 서버에서 빌드하려 하지 말 것.
  (급하면 `.java` 를 올려 `javac -encoding UTF-8 -cp <WEB-INF/lib jar> -d ...` 로 `.class` 만 교체하는 임시 수단이 있으나
   다음 배포에 덮인다.)
- **매퍼 XML 은 기동 시 로드** — 파일만 바꾸고 재기동을 안 하면 옛 SQL 이 계속 돈다.
- **JSP 는 즉시 반영이지만 캐시가 남을 수 있다** — 안 바뀌면 Ctrl+F5, 그래도면 `work/` 삭제 후 재기동.
- **WAR 교체 직후 화면이 통째로 죽어 보이면(버튼·탭 전부 무반응, 콘솔에 엉뚱한 ReferenceError) 코드부터 의심하지 말 것** —
  브라우저가 교체 전 페이지 조각을 캐시에서 섞어 실행한 것이다. **Ctrl+F5 가 첫 조치**다.
  (2026-08-09 실제: `prdOf is not defined` 로 QPS 화면 전체가 죽어 보였으나 새로고침으로 정상 —
  커밋본에는 그 오류가 구조적으로 날 수 없는 코드였다. 판별: 콘솔 오류 줄번호가 현재 소스와 안 맞으면 캐시다.)
