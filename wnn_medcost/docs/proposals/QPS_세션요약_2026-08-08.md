## 결재선 (2026-08-09) — 2단계 완료

**결재(決裁)=승인 절차다. 요금 결제(決濟)가 아니다.** 인증 심사에 제출하려면 지표분석보고서에
결재가 찍혀 있어야 한다. 이전 시스템은 담당·팀장·부서장·이사장 4단계였다.

- **[신설] 테이블 2개 + 컬럼 1개** — [QPS_DDL_APPROVAL_2026-08-09.sql](../sql/QPS_DDL_APPROVAL_2026-08-09.sql), 운영 적용 완료.

  `TBL_QPS_REPORT.CUR_STEP`(어디까지 승인됐는지).
- **★단계 수를 코드에 박지 않는다**(진행 방식 원칙 그대로). 병원 행이 있으면 그 병원 결재선을 쓰고,
  없으면 공통 4단계. 화면 [결재선 설정]에서 `담당, 승인` 처럼 적으면 2단계가 된다 — **코드 수정 없음.**
  *[함정] 단계를 줄일 때 뒤 행이 남으면 결재가 영원히 안 끝난다 → 저장은 DELETE 후 재삽입(통째 교체).*
- **상태 전이**: DRAFT →(상신) SUBMIT →(단계별 승인) … → 마지막 단계 승인 시 **CONFIRM**.
  반려는 REJECT + `CUR_STEP=0`(처음부터 다시), 아무도 승인 전이면 **상신 회수**(CANCEL)로 DRAFT 복귀.
  *승인 요청에 화면이 보낸 `stepNo` 와 서버의 `CUR_STEP+1` 을 대조한다 — 두 사람이 동시에 눌러도 순서가 안 꼬인다.*
- **★서술 잠금(중요)**: `saveReport` 가 `STATUS=VALUES(STATUS)` 로 상태를 덮어써서 **서술을 저장할 때마다
  결재 상태가 DRAFT 로 되돌아가는** 문제가 있었다 → 해당 구문 제거 + 컨트롤러에서 SUBMIT·CONFIRM 이면 저장 거부
  (화면도 저장 버튼을 잠근다). 결재자가 본 내용과 최종본이 달라지면 안 된다.
- **권한에 대하여(솔직히)**: 시스템에 병원 내 직위·역할 정보가 없다(로그인 = `s_userid`).
  그래서 v1 은 **'누가 언제 결재했는지를 남기는 전자서명'** 이다 — 종이 결재를 그대로 옮긴 것.
  결재자 지정·대결·알림은 사용자 마스터에 직위가 생긴 뒤에 붙인다. 이름은 `s_usernm` 쿠키로 찍는다.
- **✅검증(운영 DB, 가짜 병원 → 삭제 완료)**: 기본 4단계 상속 · 2단계 승인 시 SUBMIT 유지 ·
  3단계 반려 시 REJECT+0 복귀 · 재상신 후 4단계 승인 시 **CONFIRM** · 이력 9행 순서대로 ·
  병원 전용 2단계 결재선을 넣으면 그쪽이 이김.
- 화면: 지표분석 탭 하단 **[결재] 카드** — 상태 배지, 단계별 서명칸(이름·일시), 상신/회수/승인/반려, 이력표.
