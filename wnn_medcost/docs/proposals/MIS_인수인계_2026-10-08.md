## 3. 화면별 요점

### ① 경영통계 (`main/misStat.do`)
- KPI 4(총진료비·평균 재원·입퇴원·1인 1일 진료비) · Chart.js 막대(본원 주황·고객 평균 파랑·**전년 동월 회색 점선**) · 환자군 A~E · 월별 상세(전년 동월·전년 대비 열 포함).
- 고객 평균 = 같은 달 청구를 올린 병원 전체, 20곳 미만은 「집계중」. 1인 1일 고객 평균은 20곳 이상인 가장 가까운 달.
- 전년 동월 = 고른 기간보다 12달 앞서 받아 둔다(서버 상한 24달). [엑셀출력]·[인쇄](A4 가로, `@page margin:0` 이라 브라우저 머리·바닥글 없음).

### ② 고정경비 (`main/misCost.do`)
- 항목별 월 금액, 입력 없는 달은 이전 달 값을 회색 기울임으로(저장해야 굳음). 손익분기 = 고정비 ÷ ((1인 1일 진료비 − 변동비) × 그 달 일수). **추정 월 손익** = 수익 − 고정비 − 변동비×입원일수.
- 월 저장은 지우고 다시 넣기 → `context-transaction.xml` pointcut `misCostSaveTx`(이 앱은 `@Transactional` 이 안 돈다).

### ③ 업무 알림 (`main/misAlert.do`)
- `selectAlerts` : 지난달 청구·입퇴원·평가표·자료생성·자가점검(`MagamService.select_assesCheck00`)·이번 분기 차등제·고정비·병상 + **고객관리**(연락 예정일 지남/오늘, 퇴원 7일 안부 미연락, 이번 달 상담·입원). level bad/warn/ok/info.
- 인력 시뮬레이션 = 차등제 신고값 + `TBL_WEVALUE_MST`, 계산은 화면.
- **문자·메일** : 받는 사람 표(체크한 사람에게만 [지금 보내기]) · 미리보기 · 이력. 메일 = `MailUtil`, 문자 = `SmsUtil`(설정 없으면 SKIP 기록). 자동 = `MisNotiScheduler` 평일 08:30, `noti.auto.enabled=true` 일 때만, `TBL_MIS_NOTI_RUN` 선점으로 하루 1회(운영 톰캣에 앱이 두 벌).
- **카톡 공유** = 카카오 JS SDK 텍스트 카드(사람이 카톡에서 받는 사람 고름). `kakao.properties` 의 키·도메인 등록 필요(§5). [글 복사]는 폴백.

### ④ 신규환자 고객관리 (`main/misLead.do`)
- 관리판 5칸, **칸 빈 곳 클릭 = 그 단계로 새 접수**, 카드 클릭 = 상세. 자동 매칭 = 생년월일6+이름(숫자 뗌)으로 입퇴원현황과 대조해 입원(40)/퇴원 후(50)로 **앞으로만** 옮김.
- 유입 경로 전환율(이번 달/최근 3달) · 퇴원 안부 연락(최근 N일 퇴원, 결과 저장) · [엑셀출력](상담 목록 17열 + 안부 표). 주민번호 전체는 받지 않는다.

### ⑤ 병원자료엑셀연계 (`main/misEmr.do`, 2026-10-11)
- 닥터스 EMR 직접 연계가 안 돼 엑셀로 올린다. 자료 6가지 = 수납대장(PAY) · 행위별 통계(ACT, 행위 분류 단위 — 수가코드·명칭 없음) · 삭감 내역(CUT) · 입퇴원현황(IPWON) · 환자·보호자 연락처(CONTACT) · 직원·근무(STAFF).
- 삭감은 **종별 › 지급처 단위**(환자별 아님 — SWCHMISU `CHM_RECV` 와 같은 결 · 구분 삭감/불능/조정). 그 달 청구 샘파일과 볼 때마다 맞춘다 : 종별 = 청구서 INSUR_TYPE, 지급처 = 명세서 보장기관기호(건강보험은 공단 한 곳). 청구번호 → 종별+지급처 → 종별 차례. 감액률 = 감액 ÷ 그 달 샘파일 청구액. 대상 연월 = 진료(청구) 연월.
- 견본 양식이 없어 **머리글 ↔ 항목 맞춤 화면**(자동 추천 → 사람이 고침 → 병원·자료별 기억). 합계·소계·빈 줄 자동 제외, 미리보기 30줄.
- 저장 = 그 달 통째 대체(연락처는 최신본 대체). 입퇴원은 기존 입원현황 업로드(`/main/saveExcelDatas.do`)로 같은 표에 들어간다.
- 연계 : 퇴원 안부 연락 목록에 보호자 연락처(생년월일6+이름).

## 4. 배포 순서 (운영)

1. DDL 3개 — ✅ 적용 완료(10-08). 다시 돌려도 안전.
2. **WAR 재빌드 + 재기동** (자바·매퍼·스프링 XML·kakao.properties 가 WAR 안). 배포 가이드 §3.3·§4 대로. ⚠`context-common.xml` 에 `task:` 네임스페이스가 들어갔다 — XmlBeanDefinitionReader 로 PARSE OK 확인했지만 기동 로그를 볼 것.
3. 운영 `mail.properties`(`-Dwnn.mail.config` 파일)에 두 줄 추가:
   ```properties
   noti.auto.enabled=true      # 평일 08:30 자동 발송 — 운영에서만 (개발 PC 는 false)
   sms.enabled=false           # 알리고 계정이 생기면 key/userId/sender 넣고 true (sample 참조)
   ```
4. 반영 확인 = 위너넷으로 로그인 → `m i s` 타이핑 → 메뉴 4개 → 업무 알림에서 `alertGet` 응답 `build` ≥ `20261008-MIS5`.
5. 카카오 — Kakao Developers 앱의 **JS SDK 도메인**에 `https://www.winner797.co.kr`·`https://winner797.co.kr`(·로컬 `http://localhost:8080`) 등록 완료(10-08, 키 `ea17c…`). 앱 이름이 카드 하단에 찍힌다 — WinCheck+ 로 보이려면 새 앱을 만들어 키만 바꾼다.

## 7. 함정 (오늘 겪은 것)

- perl `s|…|…|` 패턴에 JS `||` 가 있으면 전 줄이 치환된다 → Edit 도구나 `#` 구분자, 치환 뒤 `grep -c`.
- DATETIME 은 LocalDateTime 객체로 직렬화돼 화면에 `[object Object]` → 매퍼에서 `DATE_FORMAT`.
- 카카오 SDK : JS SDK 도메인은 **키마다 따로**, 경로 없이 origin 만. 팝업이 막히면 SDK 가 null 창에 손대다 TypeError — 화면이 「팝업 차단」으로 안내.
- 내장 브라우저는 내 클릭의 팝업을 막고 claude.ai 로그인을 요구한다 → 카톡 창·아티팩트 확인은 사용자 크롬으로.
- 색 이모지(🔴🟠)는 카톡 PC 에서 회색 점 → 글자(`[급함]`/`-`).
- 인쇄물의 `about:blank`·날짜·쪽수는 `@page{margin:0}` + body padding 으로 없앤다.
- 서버 검증 규칙(2026-10-01) : 함수 반환값을 글자와 비교하면 `COLLATE` — 프로시저 검증은 등록할 사람의 연결 정렬로.
