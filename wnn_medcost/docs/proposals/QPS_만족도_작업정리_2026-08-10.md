## 4. ★다음 사람이 꼭 알아야 할 함정 (오늘 실제로 겪은 것)

### (1) XSS 필터가 JSON 파라미터를 깨뜨린다 — 가장 큰 함정
파라미터의 `"` 가 `&quot;` 로 바뀌어 들어와 **JSON 파싱이 실패**한다
(`Unexpected character ('&' (code 38))`). 증상은 **「저장을 눌러도 아무 반응이 없다」**.
⇒ `QpsController.jsonRows()` 에서 파싱 전에 언이스케이프하도록 고쳤다.
**QPS 전 화면 공용 헬퍼이므로 앞으로 만드는 화면은 이 문제를 겪지 않는다.**

### (2) 진단은 이 순서로 — 화면부터 의심하지 말 것
```powershell
$s=New-Object Microsoft.PowerShell.Commands.WebRequestSession
$s.Cookies.Add((New-Object System.Net.Cookie('s_hospid','w1234567','/','localhost')))
$s.Cookies.Add((New-Object System.Net.Cookie('s_wnn_yn','N','/','localhost')))
Invoke-RestMethod -Uri "http://localhost:8080/qps/xxx.do" -Method POST -WebSession $s -Body @{...}
```
**쿠키 두 개만 붙이면 로그인 없이 API 를 직접 때려볼 수 있다.**
이 한 번이면 서버/화면 중 어디가 문제인지 즉시 갈린다.
→ ①API ②DB ③화면 순서. 오늘 이걸 늦게 해서 시간을 크게 날렸다.

### (3) 저장 버튼은 반드시 상단에
문항 20개 아래에 두었더니 사용자가 못 보고 「저장이 안 된다」로 신고했다.
지금은 **탭에 따라 상단 버튼이 바뀐다**(개요=조사정보 저장 / 응답=이 응답 저장 / 집계=없음).

### (4) select 는 값만 복원되고 change 는 안 쏜다
새로고침하면 화면엔 조사가 선택돼 보이는데 내부 상태는 비어 있다.
⇒ `ensureSurvey()` 로 저장·집계 양쪽에서 같은 규칙으로 보정한다.

### (5) ★검증 데이터를 지울 때 병원코드 전체를 지우지 말 것
`DELETE ... WHERE HOSP_CD='w1234567'` 로 정리하다가 **사용자가 방금 저장한 응답까지 날렸다.**
"저장이 안 된다"는 오진의 큰 원인이었다. **내가 만든 행만 지정해서 지울 것.**

## 5. 검증 완료 항목

- 산식 : 점수합 `SUM(SCORE)` / 총점 `COUNT(SCORE)*5` / 백분율 / 평균(점)
- ★**무응답(NULL)은 분모에서 빠진다** — 실데이터로 확인
- ★**배점 역전** : 보기 표시는 매우만족→매우불만족, 값은 **5→1**
- 전 문항(20개) × 배점(5~1) 저장·조회 왕복 일치
- 버튼 전수 : 새 조사 · 조사정보 저장 · 새 응답 · 이 응답 저장 · 삭제 · 탭 · 점수 상세 · 연도 변경
