### ④ [🖨 서식 묶음 인쇄] — 옛 「일괄 출력」 화면 개편 (JSP 2 · **미커밋**)

등록 화면 21곳에 [🖨 일괄 출력] 이 생기며 **같은 이름이 두 군데**가 됐다. 하는 일이 다르다 :

| | 하는 일 |
|---|---|
| 등록 화면 [🖨 일괄 출력] | 한 서식의 **여러 건**(업무 조건으로 걸러) |
| 메뉴 [🖨 서식 묶음 인쇄] | **여러 서식**을 한 벌로(실사·인증 준비). 서식 하나에 한 장씩(회의록만 기간 안 여러 건) |

- 메뉴·제목 이름 변경 + 첫 화면에서 두 길을 가르는 안내 띠 + 서식 줄마다 **[화면에서 →]**(그 등록 화면을 새 창으로, 고른 해를 `?yy=` 로 넘김).
- 이어서 **주기·찾기를 「작성 현황」 업무로 갈랐다** — 화면 안 **업무 탭 2개**(`🖨 묶음 인쇄` / `📋 작성 현황`).
  ⚠**화면 파일은 쪼개지 않았다** — 찾기는 인쇄와 **같은 기계**(`grab`·`frameSrc`·`message`)를 쓴다. 떼면 서식 표 127종과 그 기계가 두 벌이 되어 반드시 어긋난다.
  ⇒ 기계는 한 벌, **보이는 것만 CSS 로 가른다**(`#qpsPrintAll.m-stat` / `.m-print` · `paMode()`). JSP 가 `${param.mode}` 를 읽으므로 **자바 변경 없음.**
  ⚠★**메뉴는 한 줄이다** — 처음엔 「📋 서식 작성 현황」을 **메뉴로 따로** 냈는데 이름도 화면도 닮아 **중복으로 읽혔다**(사용자 「2개 메뉴가 살짝 중복인 것 같은데」).
    ⇒ 메뉴는 [🖨 서식 묶음 인쇄] 하나로 되돌리고 **탭으로 옮겼다.** `?mode=stat` 으로 바로 여는 길은 살려 두었다(옛 링크 호환).
    ★교훈 : **업무가 다르다고 메뉴를 나누면, 이름이 닮은 순간 되레 헷갈린다** — 화면 안에서 가르는 편이 나을 때가 있다.

### ⑤ [✍ 일괄 사인] — 세 묶음의 마지막 (JSP 1 · **미커밋**)

**뜻(사용자 확정)** = 「점검표 여러 문서의 **빈 사인 칸**을 내 이름으로 한 번에」.
⛔결재(승인)가 아니다 — 결재선이 실제로 도는 것은 **지표분석보고서뿐**이고(`TBL_QPS_APPR`+`_LINE`, 키=지표×회차), 나머지 서식은 인쇄물에 **빈 결재란만** 나간다.
이건 종이 서식의 **점검자 사인 칸**(예약 행 `SIGN_NO=900`)이다.

- 조건 = 이 서식만 / 이 부서 서식 전부 · 연도+월 범위(일괄 출력과 **같은 규약**, 「이 서식만」은 병동 필터를 따름) · 이름은 `s_usernm`.
- ★★**일괄 출력과 다르다 — 자료를 고쳐 저장한다.** ①실행 전 **반드시 묻는다** ②**빈 칸만**(이미 적힌 사인 안 덮음) ③화면의 **「토·일·공휴일 제외」** 를 따름
  ④**채울 칸이 없는 문서는 저장조차 안 한다**(수정일시를 안 건드린다) ⑤상한 200건 ⑥조건 띠는 **초록**(파란 일괄 출력과 눈으로 구분).
- `ckSave(opts)` 에 **`{quiet:true}`** 를 열었다(묻지·알리지·재조회 안 하고 저장만 + 프라미스). **저장 payload 는 여전히 한 곳에서만** 만든다.

### ⑥ 같이 잡은 결함 — 못 연 문서

`ckPickDoc` 은 실패를 `catch(err)` 가 삼켜 **앞 문서 번호(curSeq)가 그대로 남는다.**
**일괄 출력이 그 상태로 그냥 찍어 앞 문서가 한 번 더 실릴 수 있었다**(다른 QPS 화면엔 이미 있던 가드가 여기만 빠져 있었다).
⇒ 일괄 출력·일괄 사인 두 곳 모두 **열기 직전 `curSeq = 0`** 으로 내리고 열린 뒤 번호를 대조해 어긋나면 건너뛴다.

### ⑦ 부서 양식 복사·배정(qpsDeptForm) — 시연에서 나온 결함 2건 (JSP 1 · **미커밋**)

화면을 「어디 것을 어디로 복사해서 쓴다」 중심으로 다시 구성한 뒤, 사용자가 **[복사]와 [부서·분류 저장]의 차이**를 묻고 실제 동작을 시켜서 드러났다.

1. **부서를 옮기면 분류가 조용히 비워졌다.** 공통 서식 `LAB001`(진단검사·기타)의 부서만 물리재활로 바꿔 저장했더니 분류가 `기타` → **빈 값**이 됐다.
   원인은 부서 change 처리의 「새 부서 규칙에 없는 분류는 비운다」 한 줄인데, 바로 옆 분류 셀렉트는 **「지금 값은 규칙 밖이어도 남긴다」**로 만들어 두어 원칙이 서로 어긋나 있었다.
   ⇒ **비우지 않는다.** 규칙 밖이면 셀렉트에 「(규칙 밖)」으로 남고, 줄 밑에 빨간 글로 알린다. **자동 정리는 지우는 쪽이 아니라 보여 주는 쪽으로.**
2. **「고친 것 없음」일 때 저장 단추를 막아 두어 「눌러도 아무 동작하지 않는다」**는 지적을 받았다. 막힌 단추는 눌러도 아무 일이 안 일어나 **고장으로 읽힌다.**
   ⇒ 흐리게만 두고 **눌리게** 한다. 누르면 왜 할 일이 없는지 알림창이 뜬다 — 체크해 둔 양식이 있으면 **「복사하려면 위쪽 [복사]를 누르세요」**로 안내한다.

3. **저장 단추가 복사 흐름의 한 단계처럼 읽혔다.** 이 화면의 일은 「여러 부서에서 고르기 → 대상 부서로 복사」인데, 저장 단추가 머리줄에 있어 복사 띠 바로 옆에 붙어 있었다.
   ⇒ 저장 단추를 **표 위로 내리고** 색을 달리해 두 업무를 갈랐다. 이름도 **「표에서 바꾼 것 저장」**으로 바꾸고 바꾼 건수를 단추에 붙였다. 종전 이름은 무엇을 저장하는지 읽히지 않았다.
4. **고른 것만 모아 볼 길이 없었다.** 고른 양식은 부서를 옮겨 다녀도 남지만(코드로 기억한다) 다른 부서 것은 표에서 사라져 무엇을 담았는지 확인할 수 없었다.
   ⇒ 부서 칩마다 **고른 수 배지**를 띄우고, 복사 띠에 **[고른 것만 보기]** 를 넣었다. 켜면 부서와 상관없이 담은 것만 한 표에 모인다. 복사 전에 이걸로 확인하면 된다.

시연으로 바꾼 `LAB001` 은 원래 값(진단검사·기타)으로 **되돌려 놓았다**. 작성 문서가 0건인 서식을 골라 시연했다.

## 5. 다음 사람이 알아야 할 함정 (오늘 새로 얻은 것)

1. ★**응답이 전역을 덮는 조회 함수엔 순번 가드를 둔다** — `.catch(err)` 로 실패를 삼키는 구조라 순서 뒤집힘이 조용히 지나간다(§2 ③).
2. ★**실패를 catch 가 삼키면 「앞 문서가 찍힌다」** — 열기·조회 뒤에는 반드시 **키를 대조**한다(seq·연도·회차). 표식은 조회 첫머리에서 **먼저 비우고** 성공했을 때만 세운다.
3. ★**git-bash `curl` 로 한글 파라미터를 보내면 깨진 채 저장된다**(CP949) — 한글 시험 자료는 **내장 브라우저 `fetch`** 로 넣는다.
4. ★**작업본은 CRLF** — 시뮬이 `\n  };` 를 앵커로 잡으면 `\r` 때문에 빗나간다. 읽자마자 `replace(/\r\n/g,'\n')`.
5. ★**소스 시그니처를 바꾸면 시뮬 앵커도 함께 본다** — `ckSave` 에 인자를 더하자 `sim_qpsChk_ward.js` 가 깨졌다.
6. **`saveQiRpt/Topic/Fund` 는 머리 INSERT 뒤 항목 INSERT 인데 트랜잭션이 없다** — 항목에 `sort` 가 없으면(NOT NULL) 항목만 실패하고 **머리 행이 고아로 남는다.** 화면은 늘 sort 를 보내 실사용 무해, API 직접 호출 때만 문제(미수정).
7. **`surveyAnsSave.do` 의 `items` 는 `qsort` 키다** — `sort` 로 보내면 응답 머리만 저장되고 문항 점수가 안 들어간다(응답은 OK 로 온다).
8. **UI 를 지우거나 옮길지 판단할 때 「그 상태가 저장되는가」를 먼저 본다**(07-23 에 두 번 겪은 것과 같은 뿌리).
