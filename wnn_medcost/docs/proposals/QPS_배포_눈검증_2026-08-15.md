# QPS — 운영 배포 + 눈 검증 안내 (2026-08-15)

> **A1(배포)이 A2(눈 검증)를 막고, A2 가 나머지를 막는다.** 그 둘을 한 장으로 묶었다.
> 일반 배포 절차는 [배포_가이드](../배포_가이드.md) 그대로다 — 이 문서는 **이번 사흘치에만** 해당한다.
> 항목마다 「무엇을 보면 되는지」를 적었다. ***틀렸을 때 어떻게 보이는지***도 같이 적었으니
> 눈으로 가려낼 수 있다.

## 2. 눈 검증 — 순서대로 (⏱ 대략 20분 → **10분**)

> 새 조각은 **저장·복원·한글까지 DB 로 이미 확인**했다. 남은 것은 ***눈으로 보는 것*** —
> **배치·인쇄** 둘이다.
> ★**격자 칸 수는 2026-08-15 저녁에 미리 맞춰 두었다**(ⓒ 절 머리말) — 화면 숫자가 표와 다르면
> 서식이 잘못된 게 아니라 **WAR 가 안 올라간 것**이니, 그때는 §1 의 `build` 확인부터 한다.

### ⓐ 메뉴 (2분) — `사이드바 ▸ QPS`

### ⓑ safeRpt — 사진 · 라벨 · 반복행 (8분 → **4분**) · `보고서 · 서식`

> 어느 줄로 들어가나 : **교육·보건관리** → EDURPT·HLTDIARY · **의약품·혈액** → DRUGADRE ·
> **인사·원무·총무** → HRCARD · **검진·접종 결과보고서** → RPTBHEP.
> (계열 줄로 들어가면 그 유형이 미리 골라져 있다 — 셀렉트를 찾을 필요가 없다.)
>
> ✅**[2026-08-15 저녁] 아래 숫자도 미리 확인해 두었다** — `subDefs`·`lblMap`·`photoOn` 에
> 운영 DB 값을 물려 돌렸다. **6유형 전부 일치** :
> HRCARD 9벌(학력~인사발령) · HLTDIARY 4벌+6묶음 50항목 · DRUGADRE 3벌+7묶음 34항목 ·
> RPTBHEP 2벌(검진 결과·백신접종) · BLOODRTN 1벌 · EDURPT 사진 켜짐+라벨 오버라이드
> (교육일시·교육장소, **숨긴 칸 14개**).
> ⇒ ***눈으로 볼 것은 「사진 2×2 배치」와 「인쇄물 모양」뿐이다.***

| 열 것 | 볼 것 | 틀렸을 때 |
|---|---|---|
| **직원 교육 결과 보고서**(EDURPT) | 인적 칸 이름이 **사고 서식 이름이 아니다**(교육명·강사 등) · 사진칸 **2×2** | 「환자명」·「사고일시」가 보이면 LBL_JSON 미적용 |
| 〃 **인쇄(A4)** | 사진이 종이에 **2칸씩** 찍힌다 | 사진 자리가 비면 **이미지 로드 대기**가 안 된 것 |
| **인사 기록 카드**(HRCARD) | 반복행 표가 **9벌**, 벌마다 이름 띠 + [행 추가] | 표가 1벌만 나오면 SUBS 미적용(옛 WAR) |
| **보건관리 업무일지**(HLTDIARY) | 체크 **6그룹 50항목** + 소표 **4벌** | — |
| **의약품 부작용 보고 평가서**(DRUGADRE) | 반복행 **3벌**(병력·검사치·의약품) + 체크 **7묶음 34항목** | 오늘 등록분 — 안 보이면 유형 셀렉트에 없는지부터 |
| **B형 간염 검진 결과보고서**(RPTBHEP) | 집계표가 **2벌**로 원형 복원 | 한 표로 합쳐 보이면 옛 WAR |

> ★벌 수·묶음 수는 **운영 DB 실측값**이다(HRCARD 9벌 · HLTDIARY 4벌/6묶음 50항목 ·
> DRUGADRE 3벌/7묶음 · RPTBHEP 2벌 · EDURPT `PHOTO_YN='Y'`).

### ⓒ 점검표 — 격자 칸 수 · 사진 (8분 → **3분**) · `부서별 점검표`

> ✅**[2026-08-15 저녁] 아래 6종의 「칸 수」는 미리 확인해 두었다** — 로컬 8080 이 내려가 있어
> 화면을 못 여는 대신, **배포 JSP 가 실제로 쓰는 계산 함수**(`colDefs`·`photoNms`·`preCols`·
> `docGrpCnt`·`prd` 등)를 꺼내 **운영 DB 값을 물려** 돌렸다. **6종 전부 표의 숫자와 일치**한다.
> ⇒ ***눈으로 볼 것은 「칸 수」가 아니라 「배치와 인쇄」다*** — 사진이 2×2 로 놓이는지,
> 격자가 종이 폭을 넘지 않는지. 숫자가 틀리면 그건 **WAR 가 안 올라간 것**이다.

| 부서 → 서식 | 볼 것 | 틀렸을 때 |
|---|---|---|
| 방사선 → **납가운 관리대장**(RAD022) | 대장 7열 + **사진 5칸**(사진-1·2·납·갑상선·생식선) · 인쇄에 사진 | 사진칸이 없으면 옛 WAR |
| 약국 → **응급 약품 점검 기록부**(PHA024) | 사진칸 **12개(1~12월)** | 칸 수가 다르면 `PHOTO_NMS` 확인 |
| 진단검사 → **혈당측정기 내부정도관리 점검표**(LAB030) | **연 문서**(월 셀렉트가 안 보인다) · 격자 **12행(1~12월)** × 용액 A/B | 월 셀렉트가 보이면 연 문서 전환이 안 된 것 |
| 원무·총무 → **자동 제세동기 예방 점검표**(ADM018) | 머리가 **2단 6열**(점검여부 예/아니오 · 점검결과 적합/부적합 · 조치여부 예/아니오) | 6열이 평평하면 `묶음>열` 미적용 |
| 인공신장 → **응급키트 물품 점검대장**(RNL027) | 격자 왼쪽에 **수량(고정 글자) · 유효기간(입력칸)** 두 칸 · **25행**(봉인·Laryngoscope + 물품 23) | 옆칸이 없으면 옛 WAR |
| 원무·총무 → **일상점검표 - 의료기기**(ADM012) | 기기 행 **20개** | 10개면 DB 보정이 안 먹은 것(재캡처 반영분) |

> ★위 숫자는 **운영 DB 실측값**이다(사진 5·12칸 · RNL027 25행 · ADM012 20기기 · ADM018 8항목 6열).
> 화면 숫자가 이와 다르면 **WAR 가 옛것**이거나 병원이 서식을 고친 것이다.

### ⓓ 인쇄 마무리 (2분)

> ✅**[2026-08-15 저녁] 인쇄 「구조」도 미리 확인했다** — `photoTblHtml`·`rowTblHtml` 을 꺼내 돌렸다 :
> 사진 4·3장 → **2줄(2칸씩)** · 2·1장 → 1줄 · 0장 → **아무것도 안 넣음** ·
> 반복행은 **값이 있는 벌만** 종이에 나온다(벌 1·3 만 채우면 표가 2개, 표2 없음).
> ⇒ ***눈으로 볼 것은 「구조」가 아니라 「실제로 종이에 예쁘게 앉는가」다.***

- [ ] 점검표 하나를 **인쇄 미리보기**까지 — 격자가 종이 폭을 넘지 않는지
- [ ] 사진이 있는 서식(EDURPT) 인쇄 — 사진이 **빈 칸 없이 제대로 그려지는지**
      (구조는 맞으니, 볼 것은 **blob 이 제때 그려졌는지**뿐이다 — 안 그려졌으면 회색 빈 칸으로 나온다)
