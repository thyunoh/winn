⇒ 지금 운영은 **평소대로 돌아간다.** 배포하면 그때 화면에 나타난다.

### 배포하면 되는 것 (사용자가 직접)

자바 2 · 매퍼 XML 1 · JSP 2 가 섞였으므로 ***WAR 재빌드 + 재기동***이다
([배포_가이드](../배포_가이드.md) §2 표 그대로). DDL·시드는 **다시 돌리지 않는다.**

```

② webapps/wnn_medcost-1.0.0 에 전개   ← ★ROOT 아님(2026-08-07 에 여기서 한참 헛돌았다)
③ /usr/share/tomcat9/bin/shutdown.sh → ps 로 0 확인 → startup.sh
   ⚠systemctl restart tomcat9 금지(유령 인스턴스를 건드린다)
```

**반영됐는지 확인** — QPS 응답의 `build` 표식이 **`20260812-FACSEED`** 면 새 WAR 다.
(옛 값은 `20260812-PRDSUB`. 다르면 clean 을 빼먹었거나 다른 폴더를 본 것이다.)

⇒ 근거 없이 반만 복사하는 대신 **서식이 열을 지목한다**(`CARRY_YN`). 어느 칸이 따라오는지

## 6. 이 세션에서 새로 배운 함정

| 함정 | 증상 |
|---|---|
| **열 이름 속 쉼표** | `COL_NMS` 는 쉼표로 열을 가른다 — `점검결과 (양호 ○, 불량× )` 를 그대로 넣으면 **열이 둘이 되어 조용히 표가 틀어진다.** ***오류가 안 난다.*** `COL_NMS`·`HEAD_NMS`·`PRE_COLS`·`POST_COLS`·`SIGN_LINE`·`ROW_BLKS`·`PRD_SUB` 전부 해당 |
| **체크박스의 `value`** | 항목표에서 `el.value` 로 읽으면 체크박스는 늘 `'on'` — 그대로 담아 `CARRY_YN` 이 전 열에 켜질 뻔했다(`el.checked` 로 고침) |
| **머리글과 몸통은 같이 숨긴다** | 항목표에 칸을 더할 때 `<th>` 만 숨기면 표가 한 칸씩 밀린다 — `data-cell` 로 몸통도 같이 |
| **블록이 갈리면 묶음도 끊는다** | 안 끊으면 이웃 블록의 같은 이름 묶음이 rowspan 으로 이어져 **묶음 칸이 띠를 뚫고 내려간다** |
| **같은 이름 띠 둘은 띠가 아니다** | 원본이 머리글을 되풀이한 것이다(FAC017·FAC038). 블록으로 세우면 없는 구조를 만든다 |
| **원본 트리에 같은 이름이 두 번** | 소방시설 일일점검표 · 의료가스 일상점검 · 소화기 관리대장 · 시설물 정기점검. **꼬리 쪽이 늘 새것은 아니다**(cap174 는 꼬리가 「사용중지」) ⇒ **내용으로 가른다** |

### ⛔`.claude/worktrees` 가 커밋되면 **push 가 500 으로 막힌다** (2026-08-12 실제 발생)

Claude Code 가 만든 임시 worktree 폴더를 git 이 ***SHA 가 전부 0 인 gitlink***(`160000 000000…`)로
인덱스에 넣고, 그게 **커밋까지 되면** 그 뒤로 `status`·`commit`·`push` 가 전부 막힌다.

- 증상 ① `error: cache entry has null sha1: .claude/worktrees/…`
- 증상 ② **eGit push 가 `500 Internal Server Error`** — GitHub 이 null-sha 객체를 거부하는 것이다.
  ***네트워크·권한 문제로 오진하기 딱 좋다.***
- ⚠**나중에 지우는 커밋을 얹어도 안 풀린다** — push 는 커밋을 통째로 보내므로
  ***옛 커밋 안의 나쁜 트리가 그대로 전송된다.*** **그 커밋들을 고쳐야 한다.**

**푼 방법** (아직 원격에 없는 로컬 커밋이라 안전했다) :
```bash
git branch -f backup/before-worktree-fix HEAD          # ★먼저 백업
git filter-branch -f --index-filter \
  'git update-index --force-remove .claude/worktrees/fav-max-2 .claude/worktrees/fav-menu-2 2>/dev/null || true' \
  -- origin/main..HEAD
git diff backup/before-worktree-fix HEAD               # ★비어야 한다(파일 내용 동일 확인)
```
⇒ 커밋 6개 유지, 해시만 바뀜, **파일 내용 차이 0**. 재발 방지로 `.gitignore` 에
`**/.claude/worktrees/` 를 넣었다(왜 막히는지 주석과 함께).

### ⚠못 하는 조합 하나

**고정 띠 + 인쇄 열-끊기(`SPLIT_DIR='C'`)** — 띠 칸에 `data-day` 가 없어 조각마다 통째로 남는다.
근거 서식 3종이 전부 안 끊는 판이라 **지금은 부딪히지 않는다.** 부딪히면 그때 고친다.

## 7. 검증할 때 지킨 것 (다음에도)

- 가짜 병원 **`99999998`** 로만 저장하고 **끝나면 지운다**(잔여 0건 확인). 실제 병원 자료에 테스트 행을 남기지 않는다.
- `DELETE ... WHERE HOSP_CD='...'` 로 싹 지우지 않는다 — **내가 만든 행만** 지정해서 지운다
  (전에 사용자가 방금 저장한 자료까지 날려 「저장이 안 된다」 오진의 원인이 됐다).
- 순서는 ①API ②DB ③화면. 쿠키 두 개(`s_hospid`·`s_wnn_yn`)면 로그인 없이 API 를 직접 때려볼 수 있다.
- 클래스·매퍼를 고쳤으면 **`web.xml` touch 로 리로드**하고, 화면이 아니라 **`build` 표식**으로 반영을 확인한다.
- ⚠**Eclipse 서버가 도는 중에 명령줄 `mvn compile` 을 돌리지 말 것**(2026-08-12 실제 발생).
  Eclipse 자동배포와 겹치면 `.class` 를 쓰는 순간을 배포기가 읽어
  ***`Publishing failed … File not found: …QpsController$1.class`*** 가 나고
  **배포 폴더의 그 패키지가 통째로 비어 버린다.** 8080 은 옛 클래스가 메모리에 남아 200 을 돌려주므로
  ***재기동 전까지 티가 안 난다.***
  ⇒ 고치는 법 : **Servers ▸ 서버 우클릭 ▸ Clean...**(전체 재배포). 소스는 멀쩡하다.
  ⇒ 피하는 법 : 검증용 빌드는 **Eclipse 빌드에 맡기거나** 서버를 멈추고 돌린다.
