## 2. 왜 이렇게 만들었나 (설계 — 되돌리기 전에 읽을 것)

- **문제** : 도장은 로그인 계정 본인만([🖋 내 도장], 결재란용) 등록할 수 있었다. 점검표 사인 칸에 이름이 오르는 **간호사·조무사는 계정이 없다** → 그 사람 사인을 붙일 길이 없고, 근무표 사람 콤보도 비었다.
- **답** : ***새 표 없이 `TBL_QPS_SIGN` 을 직원 표로 넓혔다.*** 이 표가 이미 「병원+USER_ID = 사람마다 한 줄」이라 **근무표·사인 칸·결재란이 한 사람을 가리킨다.** 직원 표를 따로 두면 사람이 두 표에 갈린다(이 저장소가 여러 번 겪은 함정 — 「같은 것을 두 군데서 하지 않는다」).
- **기존 `TBL_HOSPEMP_MST` 와 대조**(사용자 물음, DB 로 확인) : 그 표는 차등제 **면허 인력 신고**(면허종류·면허번호·입사·퇴사·주당근무시간, 키 = 면허번호+입사일). 면허자만 다루고 사번·직책이 없어 목적이 다르다 — **합치지 않았다.** 뒤에 「면허등록에서 가져오기」 다리는 놓을 수 있다.
- **키 규칙** : 계정 있으면 USER_ID = 계정(ACCT_YN=Y, 결재란 도장과 **같은 줄**) · 없으면 서버가 `P`+UUID 12자리(ACCT_YN=N). **만든 줄의 USER_ID 는 바꾸지 않는다**(결재 기록·근무표가 그 키를 가리킨다) — 계정 잇기는 새 사람일 때만 보인다.
- **퇴직자** = RETIRE_DT 가 오늘 이전. 근무표 콤보(`selectQpsSignerNames`)에서 빠지고 인사 화면은 「퇴사자 포함」을 켜야 보인다. ★**사인 칸 도장 찾기(`selectQpsSignsByNames`)는 그대로** — 옛 종이의 도장이 사라지면 안 된다. 삭제(USE_YN=N)와 퇴사는 다르다(화면 삭제 확인창이 「퇴사자는 빼지 말고 퇴사일을」이라 말한다).
- **개인정보 최소화** : 주민번호·연락처·주소는 받지 않는다(HRCARD 와 같은 원칙). 칸 = 이름·사번·직종·직책/직급·부서·입사·퇴사·차례·비고.
- **결재란은 그대로 본인만** — 이 화면은 결재를 대신 찍는 곳이 아니다. 계정을 이어 두면 그 사람 도장이 사인 칸과 결재란에 같이 쓰인다.
- **그림 저장 경로는 하나** — `signerImgSave.do` 도 `saveQpsSign`(내 도장과 같은 upsert)을 부른다.

## 6. 함정 — 오늘 새로 얻은 것

1. **새 화면 시뮬 본문 추출** : `</style>` 뒤부터 뽑으면 **style 앞에 있는 래퍼 div 가 잘려** `gel('qpsSigner')` 가 null 로 죽는다 → 인라인 `<script>` 앞까지 통째로 잡고 style·지시자·주석만 뗀다(`sim_qpsSigner.js` 머리).
2. **시뮬 `until` 이 영영 안 풀리면 프로세스가 멎는다** — 픽스처의 점 날짜 `2026.4.1` 은 6자리라 「건너뜀」이 되어 기대 3건이 안 찼다. 픽스처는 서버 규칙(8자리)과 같게.
3. **`ckSave({quiet:true})` 는 문서 목록을 다시 안 읽는다**(설계) — 시연에서 그 상태로 일괄 사인을 돌리니 방금 저장한 문서를 못 찾았다. 화면 [저장] 단추는 목록을 갱신하므로 실사용 무해. 자동화할 땐 `ckBase()` 를 한 번 더.
4. **`ckPrint()` 를 직접 부르면 도장이 안 찍힌다** — 도장 조회(`ckSignsLoad`) 뒤 인쇄하는 것은 `ckPrintGo()`. 툴바 단추가 부르는 함수를 쓸 것.
5. **한글 파라미터 실왕복은 PowerShell** `Invoke-WebRequest -Body ([Text.Encoding]::UTF8.GetBytes(...))` 로(응답도 `RawContentStream` 을 UTF-8 로 읽는다). git-bash curl 은 CP949 로 깨진다(08-08 함정 재확인).
6. `RunSql` 콘솔은 한글이 깨져 보이지만 저장은 정상 — 확인은 HTTP 응답(JSON)으로.
7. 내장 브라우저 스크린샷이 **한 프레임 늦게** 오는 때가 있다(패널이 열렸는데 안 보임) — JS 로 `offsetHeight` 를 같이 본다.

### ⑯ 면허등록에서 가져오기 (매퍼 1문 · 엔드포인트 1 · JSP)
- 인사 등록 툴바 **[👩‍⚕️ 면허등록에서 가져오기]** → 초록 띠. 차등제 **인력 신고표(`TBL_HOSPEMP_MST`)** 의 이름·직종(면허 종류 이름)·입사일·퇴사일을 후보로 보여 주고, 고른 사람을 인사 등록에 넣는다.
- 매퍼 `selectHospEmpCandidates` — **이름으로 묶는다**(한 사람이 면허를 둘 이상 신고할 수 있다) · 면허 종류는 공통코드(`Z`/`LIC_TYPE`)로 이름을 붙인다 · 이미 인사 등록에 있는 이름은 `already='Y'`.
- 엔드포인트 `signerEmpList.do`(권한 `canEditLib`). ★**등록은 화면이 줄마다 `signerSave.do` 를 부른다** — 붙여넣기와 같은 길이라 저장 규칙(날짜 검사·P키 만들기)이 한 곳에만 있다.
- 화면 : 전부 고르기 · **부서 함께 지정**(저 표의 `DEPT_CODE` 는 진료과 코드라 QPS 부서와 체계가 다르다 — 그래서 가져오며 고른다) · 「퇴사일 지난 사람도」 · 이미 있는 이름은 회색·체크 불가 · 한 줄 실패해도 나머지는 들어간다 · 끝나면 그 부서로 표를 맞춘다.
- ★**두 표를 합치지 않는다** — 저쪽은 「면허 신고」(키 = 면허번호+입사일), 이쪽은 「사람 명부」다. **베껴 오기만** 하고 뒤에 저쪽이 바뀌어도 따라가지 않는다(따라가면 사인이 딸려 흔들린다). 비고에 「면허등록에서」를 남긴다.
- ⚠**`20991231`(무기한) 관용값** — 실자료(11282991, 68명)의 `TE_DT` 가 대부분 이 값이다. 그대로 가져오면 인사 카드에 2099년이 남으므로 **2090년 이후는 퇴사일로 안 가져온다**(미리보기도 빈 칸).

### ⑰ 동명이인 도장 — 부서·재직 우선 (매퍼 · 자바 · JSP)
- 종전엔 같은 이름이 둘이면 **USER_ID 순 앞 사람** 도장이 붙었다(임의). ⇒ `selectQpsSignsByNames` 에 `deptCd` 를 받아 **①그 문서 부서 ②재직자 ③USER_ID** 차례로 준다.
- 화면 `ckSignsLoad` 가 **부서를 함께 보내고**(서식 부서, 공통이면 화면 부서 — `ckFormDept()`), 받은 목록에서 **먼저 온 것을 지킨다**(전에는 뒤엣것이 덮었다 — 차례를 매겨도 뜻이 없어진다).
- ★**부서가 바뀌면 받아 둔 도장을 버린다**(`SIGN_DEPT`) — 같은 이름이라도 부서가 다르면 다른 사람일 수 있다.
- 완전한 해결(사람 키로 매치)은 사인 칸에 이름만 남는 한 불가능하다 — ⑱ 이 그 실수를 줄인다.

### ⑱ 점검표 사인 칸에서 이름 고르기 (매퍼 1문 · 엔드포인트 1 · JSP)
- 사인 칸은 자유 글자다 — 손으로 치면 「홍길동」·「홍 길동」처럼 갈려 **도장이 안 붙는다**. ⇒ 인사 등록 명단을 **`<datalist>`** 로 붙여 고를 수 있게 했다(`signerPicks.do` · `selectQpsSignerPicks`).
- ★**입력을 막지 않는다** — 그냥 `input` 이라 명단에 없는 사람도 적을 수 있다(막으면 급할 때 못 쓴다). 부서로 좁히고(그 부서 + 부서 없는 사람) 퇴직자는 뺀다. 사인 있는 사람은 ✎ 로 보인다.
- 붙이는 자리 = `renderGrid` 끝(`ckSignPickSync`) — 격자 코드를 안 건드리고 뒤에서 속성만 붙인다. 사인 칸이 없는 서식은 묻지도 않고, 명단이 비거나 **옛 서버면 조용히 종전대로** 자유 입력.

**검증(후속 3건)** : 매퍼 XML **319문**·중복 0 · javac exit 0 · JSP 문법·태그·미정의·Swal 0 · 새 SQL 3문을 **재기동 전에 운영 DB 로 직접 태워 봄**(면허 후보가 실자료로 나온다 — 의사·약사 이름·입사일) · 시뮬 `sim_qpsSigner` **60** + `sim_qpsChk_stamp` **18**(+4) + 새 `sim_qpsChk_signpick` **11** → 전 시뮬 **458** 통과. ⛔눈 검증은 재기동 뒤.
