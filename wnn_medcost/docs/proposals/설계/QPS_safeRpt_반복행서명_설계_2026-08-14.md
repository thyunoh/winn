# safeRpt 확장 — 반복행 표 · 서명란 · 정형문구 (2026-08-14)

> **왜 이 문서** : 시설 판정 §4 ★★ 와 [간호/병동 판독](../판독/QPS_서식판독_간호병동_2026-08-13.md) §373 이 둘 다
> 「사고·고장 보고 계열을 `safeRpt` 에 유형 추가로 흡수하라」고 남겼고, 그 전제로
> ***`safeRpt` 항목표 구조부터 확인하라***고 했다. 확인했고 — **전제는 사실이었다.**
> 다만 **엔진에 없는 것이 3가지** 나와서, 그것을 더하는 설계다.

## 1. 없는 것 3가지 — 그리고 그 중 하나만 저장이 필요하다

| # | 없는 것 | 저장 필요? | 근거 서식 |
|---|---|---|---|
| ① | **반복행 표** (약품명·수량 목록) | **✅ 필요** | 의약품 반납 신청서[290] · 혈액 반납/폐기[201] |
| ② | **하단 서명란** (보고자·부서장·약사) | ❌ 인쇄 전용 | 위 + 신청서류 전반 |
| ③ | **정형 문구** ("위와 같이 …을 보고합니다") | ❌ 인쇄 전용 | 의약품 반납 신청서[290] |

②③이 인쇄 전용인 근거 — **점검표 엔진이 이미 그렇게 하고 있다.**
[qpsChk.jsp:1353-1357](../../../src/main/webapp/WEB-INF/jsp/main/qpsChk.jsp) 이
`FOOT_TXT` 를 작은 글씨 한 줄로, `SIGN_LINE` 을 쉼표로 갈라 `보고자 _____________ (인)` 로 찍는다.
***값을 받지 않는다*** — 종이에 손으로 서명하는 칸이다.

> ⚠**결재 장치(`TBL_QPS_APPR`)를 쓰면 되지 않나** — 안 된다.
> 키가 `INDI_CD + PRD_GB + PRD_KEY` 로 **지표 보고서 전용**이라 `SRP_SEQ` 문서에 그대로 못 붙는다.
> 그리고 그건 '누가 언제 승인했나'의 전자결재고, 여기 필요한 건 **종이 서명칸**이다. 성격이 다르다.

## 2. 설계 — 점검표 엔진과 **같은 이름·같은 뜻**으로 맞춘다

두 엔진이 서명·자유행 표를 각자 다른 이름으로 풀면 다음 사람이 반드시 헷갈린다.
`TBL_QPS_CHK_FORM` 이 이미 쓰는 컬럼명을 **그대로** 가져온다.

### 2-1. `TBL_QPS_SAFERPT_FORM` — 유형별 설정 (신규)

```
RPT_GB    VARCHAR(20)  PK   -- QPS_SAFERPT_GB
SUB_NM    VARCHAR(60)  NULL -- 반복행 표 왼쪽 이름 칸. 비면 이름 칸 없음
SUB_COLS  VARCHAR(300) NULL -- 반복행 표 열 이름(쉼표). ★값이 있어야 표를 그린다
SIGN_LINE VARCHAR(200) NULL -- 하단 서명란(쉼표) 예 '보고자,부서장,약 사' — 인쇄 전용
FOOT_TXT  VARCHAR(300) NULL -- 정형 문구 — 인쇄 전용
USE_YN    CHAR(1)      'Y'
```

- **행이 없으면 지금과 똑같이 동작한다**(LEFT JOIN, 전부 null). 기존 9유형은 넣지 않는다 —
  넣어 봐야 전부 null 이라 표만 지저분해진다. *필요한 유형에만 행을 만든다.*
- `HOSP_CD` 를 **두지 않는다** — 형제 표(`_DEF`·`_USE`)가 전부 병원 구분이 없다.
  safeRpt 안에서 일관되게 간다(점검표 엔진은 `HOSP_CD='*'` 를 쓰지만 그건 그쪽 관례다).

### 2-2. `TBL_QPS_SAFERPT_ROW` — 반복행 값 (신규)

```
SRP_SEQ BIGINT       PK1
ROW_NO  INT          PK2  -- 1..n, 문서가 늘린다
COL_NO  INT          PK3  -- 1..(SUB_COLS 열 수)
VAL     VARCHAR(500) NULL
```

- **`9000` 예약대를 쓰지 않는다.** 점검표 엔진이 9000+i 를 쓰는 이유는 격자 값과 **한 표**
  (`TBL_QPS_CHK_VAL`)를 공유해서 번호가 겹치면 안 되기 때문이다.
  safeRpt 에는 공유 값 표가 없어 전용 표를 두면 되고, 그러면 `ROW_NO` 는 1부터가 자연스럽다.
  ***예약번호를 이유 없이 흉내 내면 다음 사람이 "어디서 9000이 나왔나"를 찾게 된다.***
- 열 수는 `SUB_COLS` 를 쉼표로 가른 개수다. **정규화하지 않는다**(점검표 엔진 SUB_COLS 규칙과 동일).

### 2-3. 안 건드리는 것

`TBL_QPS_SAFERPT` 본문 26칸 · `_DEF` · `_USE` · `_CHK` — **손대지 않는다.**
전부 **더하기만 하는 DDL** 이라 옛 코드는 새 표를 읽지도 쓰지도 않는다 ⇒ **운영 선적용 안전**
(08-12·08-13 과 같은 판단).

## 3. 첫 적용 대상 — 의약품 반납 신청서

[간호/병동 판독 §373](../판독/QPS_서식판독_간호병동_2026-08-13.md) 의 채록을 그대로 매핑한다:

| 원본 | 우리 |
|---|---|
| `일자` · `반납시간` | `OCCUR_DT` · `OCCUR_TM` |
| `장소` | `PLACE` |
| `사유` ☐파손 ☐불량 ☐D/C ☐기타( ) | `_DEF` 묶음 `RTNRSN` (`MULTI_YN='N'`, 기타 `ETC_YN='Y'`) |
| `약 품 명` · `수량(용량)` | **`SUB_COLS='약 품 명,수량(용량)'`** ← 이번 신설 |
| `반납경위`(육하원칙에 따라 기록) **큰 칸** | `SUMMARY` |
| `위와 같이 의약품 ( )을 보고합니다.` | **`FOOT_TXT`** ← 이번 신설 |
| 서명 `보고자`·`부서장`·`약 사` | **`SIGN_LINE`** ← 이번 신설 |

> ⚠**`반납경위` 는 `W_*` 6칸이 아니라 `SUMMARY` 다.** 원본은 「육하원칙에 따라 기록」이라는
> *안내문구가 붙은 큰 칸 하나*지 육하원칙 6칸이 아니다. 6칸으로 쪼개면 원본과 인쇄물이 달라진다.

### ⚠ 시드 전에 남은 확인 2건 (판독 문서가 남긴 것)

1. **`[290]` 의약품 반납 신청서 ↔ 약국 「병동의약품 반납신청서」가 같은 것인가** —
   판독 §385 가 ***이름이 다르다***고 적어 두었고 **캡처로 본 것은 간호/병동 판뿐**이다.
   같으면 유형 하나, 다르면 둘이다. **약국 캡처와 대조해야 한다.**
2. **`[274]` 병동의약품 신청서**(반납 아님)는 채록이 `신청 일자·병동` 뿐이라 **정보가 모자란다.**

⇒ 이번에는 **엔진 부품만 확정**하고, 유형 시드는 **별도 파일**로 두어 위 확인 뒤에 돌린다.
