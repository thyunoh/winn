## 2-1. ★결정됨 — 「우리 병원 사용 서식」 화면 신설 (2026-08-18 사용자 결정)

### 왜
서식(공통 `'*'`)은 **우리가** 등록하지만, **어느 병원이 어느 서식을 쓸지**는 병원별이다.
그런데 그 스위치가 있는 `서식 관리` 는 ***위너넷 전용 화면***(`s_wnn_yn=Y`)이라
***병원 담당자가 스스로 켤 수 없다.*** 지금은 병원마다 우리가 켜 주어야 한다.

세 갈래(①우리가 계속 켜 준다 ②서식 관리를 병원에 연다 ③사용 목록만 켜는 가벼운 화면을 만든다)
중 **③으로 결정**. ②는 병원이 공통 서식을 고칠 위험이 있어 뺐다.

### 만들 것 — `qpsChkUse.jsp` (가칭 「우리 병원 사용 서식」)
- **체크와 저장, 그것뿐인 화면.** 서식을 만들거나 고치는 기능은 **넣지 않는다**(그것이 ②를 뺀 이유다).
- 목록 : 부서·분류 거르기 + 서식명 + 체크. `서식 관리` 의 왼쪽 목록만 떼어 온 모양.
- **서버는 새로 만들 것이 거의 없다** — 이미 있는 것을 그대로 쓴다 :
  - 목록 : `/qps/chkFormList.do` (cateCd·deptCd)
  - 저장 : **`/qps/chkUseSave.do`** ([QpsController.java:1439](../../../src/main/java/egovframework/wnn_medcost/qps/web/QpsController.java))
  ⇒ 새로 필요한 것은 **화면 진입 `main/qpsChkUse.do` 하나**와 JSP 뿐이다.
- 사이드바 : `점검표` 그룹, `점검표 작성` 바로 아래. **`(위너넷)` 게이트를 걸지 않는다** — 병원이 봐야 한다.

### ★한 화면을 둘이 같이 쓴다 (2026-08-18 추가 결정)
***병원 전용으로 만들지 않는다.*** 병원이 못 하면 결국 우리가 대신 설정해야 하는데,
그때 화면이 따로 있으면 두 벌을 만들고 두 벌을 고쳐야 한다.

| 보는 사람 | 화면 |
|---|---|
| **병원 담당자** | 자기 병원 것만. 병원 고르는 칸이 **없다** |
| **위너넷**(`s_wnn_yn=Y`) | 맨 위에 **병원 고르기** 칸이 하나 더 뜬다 — 병원 대신 켜 준다 |

⚠**서버에서 권한을 반드시 다시 본다.** 화면에서 칸을 숨기는 것만으로는 막이 아니다 —
  `hospCd` 를 파라미터로 받는 순간 ***병원 사용자가 값을 바꿔 남의 병원 설정을 건드릴 수 있다.***
  ⇒ `chkUseSave` 에서 **`s_wnn_yn='Y'` 일 때만 파라미터 `hospCd` 를 받고, 아니면 쿠키 값을 강제**한다.
  (`hospCd(request, p)` 헬퍼가 지금 어떻게 고르는지 먼저 확인할 것 — 그대로면 고쳐야 한다.)
- ⚠`chkUseSave` 가 **화면에 안 뜬 서식(부서 필터로 걸러진 것)까지 지켜 주는지** 확인할 것.
  `서식 관리` 의 `cfUseSave` 는 전체를 다시 받아 합치는 방식이다(qpsChkForm.jsp §cfUseSave) — 같은 규칙을 따라야
  ***부서를 걸러 놓고 저장했다가 다른 부서 서식이 통째로 꺼지는 사고***가 안 난다.

## 2-2. ✅`qpsChkUse` — 해소 (2026-08-18 `build=20260818-CHKUSE`)

전 세션이 「거르기가 안 든다」로 남겨 둔 것을 **실브라우저로 재현해 갈랐다.**

| 물음 | 실측 |
|---|---|
| 카드가 정말 안 줄어드나 | ***줄어든다*** — `#cuList .cu-item` 을 직접 세어 311 → 79(간호) → 11(간호+멸균) 확인. 개수 글자와 카드 수가 **언제나 같다** ⇒ 종전 의심 1·2번은 **아니었다** |
| 그럼 무엇이 문제였나 | ***3번(부서·분류 연동 없음)*** — 사용자 말 그대로 **「부서를 골라도 분류 칸이 6개 그대로」**. 시설을 골라 놓고 「멸균·소독」을 고르면 **0종**이 되는, ***고를 값어치가 없는 선택지***가 남아 있었다 |

### 고친 것 ① 부서 ↔ 분류가 서로 좁힌다 (`qpsChkUse.jsp` `refillSel`·`put`)

- 한쪽을 고르면 **다른 쪽 칸을 다시 짓는다** — 남은 종 수를 괄호로 적고, **0종은 아예 안 내놓는다.**
  (예 : 시설 → `전체 분류(45) · 의료기기 점검(9) · 환경·시설(21) · 안전·감염(14) · 기타(1)` — 멸균·소독은 사라진다)
- ⚠각 칸의 후보는 ***자기 조건을 뺀 나머지***로 센다 — 자기 조건까지 넣으면 **고른 하나만 남는다.**
- ⚠지금 고른 값이 0종이 되어도 **지우지 않는다.** 칸이 저 혼자 바뀌면 「내가 안 골랐는데」가 된다.
- 검색어(`cuQ`)도 같은 규칙으로 두 칸에 반영된다.
- 검증(실브라우저) : 시설→분류 4개 · 시설+환경·시설 **21종** · 부서를 전체로 되돌리면 분류 6개 복귀(70종) ·
  **분류만 골라도 부서 칸이 좁아진다**(환경·시설 → 감염관리·보건관리자 사라짐) · 검색어 겹침(12종) 전부 통과.

### 고친 것 ② ★★병원 계정이 목록을 아예 못 받고 있었다 (`QpsController.chkFormList`)

***이 화면을 만든 이유가 「병원이 스스로 켠다」인데, 정작 병원 계정에는 목록이 안 왔다.***

- `chkFormList.do` 에 **위너넷 전용 게이트**(`isWnn`)가 남아 있어 `s_wnn_yn≠Y` 면
  `FAIL — 서식 관리는 위너넷 담당자만` 을 돌려줬다. 화면은 경고창만 뜨고 **텅 빈다.**
- ⇒ **읽기 하나만 열었다.** 서식을 만들고 고치는 5개(`chkFormSave`·`chkFormCopy`·`chkFormDel`·
  `chkCodeAdd`·`chkCodeNext`)는 게이트 그대로다.
- 검증 : `s_wnn_yn=N` 으로 목록 **OK(311종)** · 같은 계정으로 `chkFormSave` 는 여전히 **FAIL** ·
  병원 계정이 `hospCd` 를 위조해도 `hospCd()` 가 쿠키 값을 강제한다.

### ✅`INF001`·`INF002` 시드 반영 확인됨
