## 4. 새 부품 — 점검표 엔진과 **같은 이름**으로 맞췄다

`SUB_NM` · `SUB_COLS` · `SIGN_LINE` · `FOOT_TXT` — 전부 `TBL_QPS_CHK_FORM` 에서 그대로 가져온 이름이다.
두 엔진이 같은 것을 다른 이름으로 부르면 다음 사람이 반드시 헷갈린다.

- **`SIGN_LINE`·`FOOT_TXT` 는 값을 받지 않는다 — 인쇄 전용.**
  점검표 엔진([qpsChk.jsp:1353-1357](../../src/main/webapp/WEB-INF/jsp/main/qpsChk.jsp))이 이미 그렇게
  `보고자 _____________ (인)` 로 찍고 있다. **종이에 손으로 서명하는 칸**이라 저장할 값이 없다.
- **결재 장치(`TBL_QPS_APPR`)는 쓸 수 없다** — 키가 `INDI_CD+PRD_GB+PRD_KEY` 로 **지표 보고서 전용**이라
  `SRP_SEQ` 문서에 안 붙는다. 성격도 다르다(그건 전자결재, 이건 종이 서명칸).

### ★`9000` 예약대를 쓰지 않았다 — 이유

점검표 엔진이 자유행 표를 `9000+i` 에 두는 것은 **격자 값과 한 표**(`TBL_QPS_CHK_VAL`)를 공유해
번호가 겹치면 안 되기 때문이다. safeRpt 는 **전용 표**(`_ROW`)라 `ROW_NO` 가 1부터인 것이 자연스럽다.
***이유 없이 9000을 흉내 내면 다음 사람이 "어디서 9000이 나왔나"를 찾게 된다.***

JS 로 확인할 수 있다.*** (패널이 안 보이면 사용자도 못 누르니, **사용자 Chrome 으로 8080 에 로그인**하고
그 브라우저에서 확인하는 편이 빠를 수 있다.)

### 왜 못 했나 — 브라우저가 갈렸다

화면 검증에는 로그인 세션이 필요한데 **자동화 브라우저와 사용자의 Chrome 이 세션을 공유하지 않는다.**
- 내장 Browser 패널 = 쿠키 별도. 게다가 **패널이 화면에 표시되지 않으면 사용자가 로그인할 수 없다**
  (스크린샷도 `the Browser pane is not displayed` 로 실패한다).
- `Claude in Chrome`(실제 Chrome, 기존 로그인 재사용)은 **확장이 이 PC 에 설치/로그인되어 있지 않다.**
- ⚠**세션 판정은 쿠키로 하지 말 것** — `JSESSIONID` 가 **HttpOnly** 라 `document.cookie` 에 안 보인다.
  ***`/qps/safeRptBase.do` 를 same-origin fetch 로 때려 `"로그인이 필요합니다"` 인지 보는 것이 확실하다.***

⇒ **다음 세션의 첫 일감**(§6 ⓐ). 화면만 열면 5분이면 끝난다.

### 남은 확인 항목 (그대로 유효)

***특히 한글 왕복을 확인해야 한다*** — `rows` 는 `chks` 와 같은 `jsonRows()` 경로를 타는데,
08-13 §5-4 가 「curl 로 넣은 한글은 깨져 저장될 수 있다 — 한글 왕복은 화면 저장으로 확인한다」고 남겼다.
반복행에는 약품명이 들어가므로 **반드시 화면에서** 확인할 것. 가짜병원 `99999998`.

**검증 방법** : `TBL_QPS_SAFERPT_FORM` 에 임시 1행을 넣어 아무 유형에나 `SUB_COLS` 를 걸고 →
화면에서 한글 품목 저장 → 다시 열어 복원 → 인쇄 → ***임시행 삭제***.
(오늘 `SECU` 로 그렇게 해 두었다가 **검증을 못 해 지웠다** — 지금 설정표는 0행이다.)
