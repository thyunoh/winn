# 점검표 엔진 v3 — 설계안 (2026-08-12)

> 근거 : 약국 26종 · 영양 25종 · 시설 60여 종을 실물 캡처로 판정한 결과.
> [약국](QPS_서식판정_약국_2026-08-12.md) · [영양](QPS_서식판정_영양_2026-08-12.md) · [시설](QPS_서식판정_시설_2026-08-12.md)
> 판정 기준은 [세션요약](QPS_세션요약_2026-08-08.md) 의 「엔진을 보완할까, 직접 만들까」.
>

## 0. 결론 한 줄

***축 이름을 더 만들지 않는다. 「네 가지 선택의 조합」으로 바꾸고, 화면에는 자주 쓰는 조합에만 이름을 붙인다.***

---

## 1. 왜 — 축 이름이 감당이 안 된다

v2 까지 축은 다섯이었다(`ITEM_DAY`·`DAY_ITEM`·`EQUIP_DAY`·`ITEM_MONTH`·`LIST`).
세 부서 실물을 보고 나니 **새 이름 후보가 열 개를 넘었다** :

`ITEM_COL`(13종) · 주차 열(4) · 요일 열(3) · `MONTH_ITEM`(1) · `EQUIP_MONTH`(3) ·
분기 열(1) · 항목 설명 열(3) · 항목 뒤 열(3) · 행 블록(6) · 문서가 정하는 열(2) ·
문서가 정하는 행(1) · 반달 3종(7) · 연간 모아 인쇄(2)

***이대로 이름을 붙이면 서식 관리 화면의 「표 모양」 셀렉트가 스무 줄이 된다.***
세션요약이 적어 둔 **「멈추는 신호」** — *축이 계속 늘어 서식 관리 화면이 점검표 자체보다
어려워지면 거기서 그만둔다* — 에 정확히 걸린다.

### ★그런데 뜯어 보면 전부 같은 조각의 조합이었다

**소화기 관리대장(연단위)** 하나가 이걸 보여 준다. 「`EQUIP_MONTH` 라는 새 축이 필요하다」고 봤는데 :

| 필요한 것 | 상태 |
|---|---|
| 자유행 | `LIST` 에 **이미 있다** |
| 1~12월 열 | `ITEM_MONTH` 에 **이미 있다** |
| 행 그룹(층) | v2 에서 **이미 만들었다** |
| 행 앞 열(설치 위치·종류) | 「항목 설명 열」 — 3종으로 기준 도달 |
| 월마다 하위 열(점검자·결과) | 열 묶음 — **이미 있다** |

***새 축이 아니라 조합이었다.***

## 2. 네 가지 선택

| # | 선택 | 값 |
|---|---|---|
| **가** | **행이 무엇인가** | `항목` / `기간` / `자유행` / **`문서가 정하는 목록`**(기기·위치) |
| **나** | **열이 무엇인가** | `항목` / `기간` / `서식이 정한 고정열` / **`문서가 정하는 열`**(층·물질) |
| **다** | **기간 종류** | 일(1~31) · 월(1~12) · **주차(1~5)** · **요일(월~일)** · **분기(1~4)** |
| **라** | **문서 단위** | 연 · **반기** · **분기** · 월 · **주** · **일** |

***가·나 중 하나는 반드시 `항목`이거나 `자유행`이다*** — 둘 다 기간이면 표가 아니라 달력이 된다.

### 지금 축 다섯은 이 조합에 이름을 붙인 것이다

| 이름 | 행 | 열 | 기간 |
|---|---|---|---|
| `ITEM_DAY` | 항목 | 기간 | 일 |
| `DAY_ITEM` | 기간 | 항목 | 일 |
| `ITEM_MONTH` | 항목 | 기간 | 월 |
| `EQUIP_DAY` | **문서가 정하는 목록** | 기간 | 일 |
| `LIST` | 자유행 | 항목 | — |

### 새로 나온 것들도 전부 이 표에 들어간다

| 실물 | 행 | 열 | 기간 |
|---|---|---|---|
| 발전기 운전 점검일지 (`ITEM_COL`) | 항목 | **고정열**(결과·비고) | — |
| 냉·난방필터청소점검일지 (`MONTH_ITEM`) | 기간 | 항목 | 월 |
| CCTV 점검표 | 항목 | 기간 | **주차** |
| 식중독 예방 위생 점검 일지 | 항목 | 기간 | **요일** |
| 온도 관리 기록지 | 기간 | 항목 | **요일** |
| 건축물 안전 점검 일지 | 항목 | 고정열 | **분기** |
| 냉난방기 점검표 | **문서가 정하는 목록**(층·호실) | 고정열 | — |
| MSDS 관리대장 | 기간 | **문서가 정하는 열**(물질) | 일 |
| 소화기 관리대장(연) | 자유행 | 기간 | 월 |

***한 줄도 예외가 없다.*** 이것이 조합으로 가야 하는 이유다.

## 3. 격자에 얹는 것 — 축과 **직교**한다

축이 무엇이든 따로 켜고 끌 수 있다. 그래서 축의 조합에 넣지 않는다.

| 기능 | 종수 | 상태 |
|---|---|---|
| **행 그룹**(2단 행 머리글) | **5+** | ✅ v2 에서 만듦. ***가장 크게 쓰인다*** — 3단 머리글을 누르는 데도, 품목별 하위 속성에도 |
| **열 묶음**(2단 열 머리글) | 다수 | ✅ 이미 있음 |
| **항목 설명 열**(격자 앞) | 3 | 청소방법 · 시행 |
| **항목 뒤 열** | 3 | 예산 · 조치사항 |
| **행 블록**(한 문서에 표 여럿, 열은 같음) | **6** | ***`LIST`·`ITEM_COL` 양쪽에 필요*** → 축별이 아니라 격자 공통 |
| 상단 자유칸 `HEAD5~8` | **8** | ***가장 오래 밀린 것*** |
| 문서가 정하는 **열** 이름 | 2 | `EQUIP_DAY` 의 기기명(`CHK_ROW`)과 대칭 → `CHK_COL` |

## 4. 인쇄는 **자료가 아니다** — 따로 둔다

***★이 엔진을 만든 이유가 「그림처럼 만들면 뽑을 수 없다」였다.***
원본이 종이 한 장에 담으려고 만든 모양을 자료 구조로 옮기면 그 이유를 스스로 깬다.

| 인쇄 배치 | 종수 | 뜻 |
|---|---|---|
| **반달 접기** | **7** | 한 장을 **둘로** — 1~15/16~31 · 1~6월/7~12월 · **좌우 2단** |
| **연간 모아 찍기** | **2** | 열두 장을 **하나로** — 세탁물집하장 소독점검대장 · MSDS보관소(연) |

둘은 **같은 「인쇄 배치」 기능의 양쪽 끝**이다.
⚠**지금 코드는 `CUT = 15` 고정**이라 첫 줄만 맞는다. 「절반으로 나눈다 + 접는 방향」으로 일반화한다.

***★특히 「연간 모아 찍기」를 자료로 옮기면 안 된다.*** 12개월 블록을 행 블록으로 담으면
항목이 5×12=60행이 되고 **추출에서 「몇 월 것인지」가 항목명에 섞인다.**
문서는 월별로 두고 인쇄만 모은다.

## 5. 문서 단위 — 칸을 늘리지 말고 **한 쌍**으로

지금 `TBL_QPS_CHK_DOC` 은 `IN_YEAR` + `IN_MM` 뿐이다. 실물에는 여섯 단위가 나왔다.

```
PRD_GB='Y'              → 2026년
PRD_GB='H', PRD_NO=2    → 2026년 하반기      (유해화학물질 적정취급상태 모니터링)
PRD_GB='Q', PRD_NO=3    → 3분기
PRD_GB='M', PRD_NO=8    → 8월                (지금의 IN_MM)
PRD_GB='W', PRD_NO=3    → 8월 3주차          (온도관리기록지 · 소독일지 3형제 …)
PRD_GB='D', PRD_NO=12   → 8월 12일           (폐기 의약품 대장 · 발전기 운전 점검일지)
```

`PRD_GB` 는 **이미 서식 정의에 있다**(M/Y). 그걸 문서에도 두고 번호를 하나 붙이면 여섯이 다 담긴다.
***주차 칸을 따로 더하면 반기·분기가 나올 때 또 더해야 한다.***
★표기·정렬 규칙은 **QPS 지표의 반기 구분**에서 가져온다(이미 있다).

## 6. 화면은 어떻게 보이나 — ***조합을 그대로 노출하지 않는다***

내부는 조합, **화면은 지금처럼 이름 붙은 목록**이다.

```
표 모양 *  [ 점검항목(행) × 1~31일(열) — 가장 흔함        ▾ ]
           [ 1~31일(행) × 점검항목(열)                      ]
           [ 기기 N대(행) × 1~31일(열)                      ]
           [ 점검항목(행) × 1~12월(열) — 연 1장             ]
           [ 대장 — 항목(열) × 자유행                       ]
           [ 점검항목(행) × 결과·비고 등 고정 열   ← 새로   ]
           [ 점검항목(행) × 주 단위(요일/주차)     ← 새로   ]
           ───────────────────────────────
           [ ⚙ 직접 조합하기                      ← 위너넷만 ]
```

- 병원 담당자는 **이름만 고른다.** 지금과 똑같다.
- **「직접 조합하기」는 위너넷 전용**(`isWnn()`)으로 숨긴다 — 서식 관리 자체가 이미 위너넷 전용이지만,
  조합까지 여는 것은 **새 모양이 나왔을 때 개발자가 쓰는 문**이다.
- ***새 조합이 필요해지면 목록에 한 줄 더할 뿐, 코드를 안 고친다.*** 이것이 이 설계의 값이다.

## 7. DDL — 무엇이 실제로 바뀌나

| 표 | 변경 | 성격 |
|---|---|---|
| `TBL_QPS_CHK_FORM` | `ROW_GB` · `COL_GB` · `PRD_KIND`(기간 종류) 추가. `AXIS_GB` 는 **남겨 둔다** | 더하기 |
| 〃 | `HEAD_NMS` 는 그대로(쉼표 목록이라 8칸도 들어간다) | 없음 |
| `TBL_QPS_CHK_DOC` | `HEAD5~HEAD8` · `PRD_GB` · `PRD_NO` 추가 | 더하기 |
| `TBL_QPS_CHK_ITEM` | `DESC_TXT`(항목 설명 열) · `BLOCK_NO`(행 블록) 추가 | 더하기 |
| **`TBL_QPS_CHK_COL`** | **신설** — 문서가 정하는 열 이름(`CHK_ROW` 의 대칭) | 새 표 1개 |

***★`AXIS_GB` 를 지우지 않는다.*** 기존 서식 12종 + 이번에 만들 시드가 그 값을 쓰고 있다.
**조합 컬럼이 비면 `AXIS_GB` 로 해석**하게 두면 기존 자료가 그대로 산다.
⇒ **더하기만 하는 DDL. 기존 서식·문서는 하나도 안 바뀐다.**

## 8. 순서 — 무엇부터

| 순 | 무엇 | 근거 종수 | 왜 먼저인가 |
|---|---|---|---|
| 1 | **상단 자유칸 `HEAD5~8`** | **8** | ***가장 오래 밀렸고 가장 싸다.*** 컬럼 4 + 매퍼 4줄 + `slice(0,8)`. 격자·추출·인쇄를 안 건드린다 |
| 2 | **`ITEM_COL`**(항목 × 고정 열) | **13** | ***단일 최대.*** 열 이름을 서식이 정하게 하면 Y/N·예/아니오/해당없음·결과/비고·분기가 전부 덮인다 |
| 3 | **문서 단위 `PRD_GB`+`PRD_NO`** | 주 6 · 일 3 · 반기 1 | 4·5 의 **전제**다. 이게 없으면 주 단위 축을 만들어도 문서를 못 만든다 |
| 4 | **기간 종류 일반화**(주차·요일·분기) | **8** | 3 이 끝나야 뜻이 있다 |
| 5 | **행 블록** | **6** | `LIST`·`ITEM_COL` 양쪽에 필요 — 격자 공통으로 |
| 6 | **인쇄 배치 일반화**(반달 + 연간 모아) | 7 + 2 | ***지금 코드가 `CUT=15` 고정이라 이미 반쪽이다*** |
| 7 | 항목 설명 열 · 항목 뒤 열 | 3 + 3 | |
| 8 | 문서가 정하는 열(`CHK_COL`) | 2 | `CHK_ROW` 의 대칭이라 만들 때 싸다 |
| 9 | **전월 복사** | 다수 | 축이 아니라 편의 기능. ⚠아래 |

⚠**전월 복사는 「무엇을 복사할지」를 반드시 정하고 만든다.**
자산 목록(위치·규격)은 복사하고 **점검 결과는 비워야** 한다.
***전부 복사하면 지난달 결과가 남아 「점검했다」로 보인다.*** 위험한 기본값이다.

## 9. 하지 않는 것 — ***여기가 경계다***

| 안 하는 것 | 왜 |
|---|---|
| **항목별 선택지 목록**(「청결/미흡/불량」이 항목마다 다름) | **1종**(일일위생안전청소점검일지)뿐. 「이용/제공/열람/파기」는 글자로 적어도 뜻이 온전하다 |
| **리치텍스트 안내**(표 + 사진) | **7종**으로 기준은 넘었지만 ***점검표 엔진이 아니라 다른 물건이다.*** 치료식 안내문 5종은 별도 화면으로 가는 게 맞다 |
| **부가 입력표**(「문제 발생시」) | **4종.** 격자 밖에 작은 표가 하나 더 붙는 것 — ***격자 하나라는 전제를 깬다.*** 5·6 이 끝난 뒤 다시 판단 |
| **한 문서에 구조가 다른 표 여럿** | 비상발전기 운전 점검기록표 — ***억지로 넣으면 둘 다 이상해진다.*** 개별 화면 |
| **사진** | 격자는 엔진, 사진은 **이미 있는 공통 파일첨부**. 축을 늘려 될 일이 아니다 |

***★멈추는 신호를 다시 적어 둔다*** : 서식 관리 화면이 점검표 자체보다 어려워지면 거기서 그만둔다.
조합을 화면에 그대로 노출하지 않는 이유가 이것이다.

## 10. 이 설계로 무엇이 달라지나

| | v2 (지금) | v3 (이 설계) |
|---|---|---|
| 새 모양이 나오면 | **축을 만들고 코드를 고친다** | **목록에 한 줄 더한다** |
| 축 개수 | 5 → 15+ 로 늘 참 | **4가지 선택**으로 고정 |
| 서식 관리 화면 | 셀렉트가 스무 줄이 될 참 | 지금과 같은 길이 |
| 기존 서식 12종 | — | **하나도 안 바뀐다**(`AXIS_GB` 유지) |

세 부서 110여 종 중 **격자인 것이 100종 가까이**고, 그 전부가 위 조합 안에 들어간다.
***간호/병동에서 새 모양이 나와도 조합에 들어갈 가능성이 높다*** — 그것이 이 설계의 목적이다.
