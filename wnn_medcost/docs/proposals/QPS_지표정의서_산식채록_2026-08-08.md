## 0.1 ★정의서 실물 확인 (2026-08-08 캡처, 손위생) — '채록'의 성격이 바뀐다

**지표정의서는 산식이 인쇄된 문서가 아니라 병원이 채우는 빈 양식이다.**
지표명·지표정의·분자·분모·포함기준·제외기준이 전부 **빈 칸**이고, 서식에 박혀 있는 것은
지표별 하드코딩 조각뿐이다: 목표값 라벨("손위생수행률 %")과 **상수(×100)**.

→ 따라서 "SUNWOO에서 산식을 베껴온다"는 계획은 절반만 성립한다:
- **캡처에서 얻을 것** = 지표별 **상수(×100/×1000)·단위·목표값 라벨** 뿐.
- **정의 문구(분자·분모·포함/제외기준)의 원천은 결국 병원 담당자다** — SUNWOO에서도 사람이 적었고,
  낙상 지표분석 실물에서 채록한 문구도 담당자가 타이핑한 값이었다.
- 우리 `TBL_QPS_INDI_MST` 가 바로 이 양식의 그릇이다 — **위너넷에 '지표정의서 편집 화면'을 만들면
  SUNWOO 정의서 서식 자체를 대체**한다(분석문서 4.1에서 예정했던 방향이 실물로 확인됨).

**손위생 캡처에서 확정된 것**: 단위 **%**, 상수 **×100** (시드 잠정값과 일치 → 확정 처리).

**정의서 양식의 전체 필드** (위너넷 정의서 화면·마스터 확장 시 이 목록대로):
해당영역(환자안전/질환/진료/관리) · 주관부서 · 담당자 · 선정배경 · 지표명 · 지표정의 ·
분자/분모(+상수) · 포함기준 · 제외기준 · 목표값 · 이전값 · 목표값근거(의료기관인증/학회/전년도/타기관/기타) ·
자료출처(전산정보/의무기록/조사표/보고서/기타) · 자료분석 · 산출주기 · 보고주기(월/분기/반기/년/기타) ·
보고범위(감염관리위원회/QPS위원회/…) · 성과공유 대상/방법 · 비고 · 보고일 ·
**결재 4단계(담당·팀장·부서장·이사장)** ← 종전 추정(2단계)보다 길다. 결재 설계 시 반영.

## 0.3 남은 지표 산식 = DB 추출 불가 확정 (2026-08-08 밤, 3경로 소진)

→ 산식(분자·분모 라벨)은 **Delphi 폼에 하드코딩**돼 있고 exe는 패킹됨. **화면 캡처가 유일한 경로**(재확인).

0000/1000/2000(선우·재활·노인전문)에 `TfrmQPS_Insane_*` 폼으로 **자살자해(B000123~)·격리지침(B000129~)·
강박지침(B000135~)·환자안전분석(B000142~)** 이 별도 존재(0001 SRC 트리엔 없던 것). 격리·강박은
기록지·시행일지(D000027~29)까지 딸린 정신과 특화 세트다. → **병원 유형(재활/정신)에 따라 지표 집합이 다르다**
는 뜻. 위너넷 마스터는 이미 HOSP_CD 별 덮어쓰기 구조라 흡수 가능하나, 지표 목록에 이 4종을 명시해 둔다.

**남은 캡처 목록(이것만 오면 마스터 UPDATE로 끝)**:
직원안전 · 의료서비스(환자만족도) · 투약 · 재택복귀 정의서 / 환자안전·자살자해·격리·강박·학대폭력 분석보고서.

## 1. ✅ 낙상 발생 보고율 — 확정

실물 문서 3건(`B000028` 1/4분기, `B000029` 2/4분기, `B000032` 중간보고서, COMPANY=1000 SRC재활병원)에서 채록.

| 항목 | 값 |
|---|---|
| 지표명 | 낙상 발생 보고율 |
| 정의(산출식) | **환자 1,000 재원일당 낙상 발생 건수의 비율** |
| 분자 | **낙상 발생 보고 건수(Level 2 이상)** |
| 분모 | **재원환자 연인원수** (해당 기간 일일 재원환자 수의 합 = 총재원일수) |
| 계산 | `분자 ÷ 분모 × 1,000`, 단위 **‰(퍼밀)**, 소수 2자리 |
| 주기 | 분기별 (+ 중간(상반기)·최종 보고서) |
| 자료원 | 환자안전사고보고서 |
| 집계방법 | 통계집계프로그램 |
| 담당 | QPS담당자 |
| 서명 | 담당(img_A) · 팀장(img_B) |

**검산 (실제 저장값으로 확인 — 산식이 맞음)**

- 1/4분기: 월별 낙상 2·0·0건, 총재원일수 1,000·1,000·1,000
  → 월별 2.00‰ / 0.00‰ / 0.00‰, 분기 2 ÷ 3,000 × 1,000 = **0.67‰** ✓
- 중간(상반기): 누적 3건 ÷ 6,000일 × 1,000 = **0.50‰** (1분기 0.33‰, 2분기 0.67‰의 가중평균) ✓

**분모의 출처가 DB에 있다** — `T_PATIENTCNT`(COMPANY, GUBUN, IN_YEAR, M01~M12):
`GUBUN='총재원일수'`, `GUBUN='월별직원수'` 두 행에 월별 값. 트리의 「05 월별재원환자수 및 직원수」가 이것.
→ 위너넷에서도 **분모 마스터 테이블 1개(월×병원×구분)**로 그대로 옮기면 된다.

**세부 집계 축** (보고서가 요구하는 분류 — 사고보고서 입력 항목이 이만큼 필요하다는 뜻)

연령대 · 손상유형 · 사고유형 · 발생장소 · 발생시간대 · 낙상유형 · 보고부서 · 그룹(전년/타병원) 비교.

## 2. 🟡 TAT (검체/영상) — 집계 축만 확인

`T_RPT` 테이블이 지표 집계 전용 키·값 저장소다(CHART_ID `Q010011`, COMPANY=2000):

| RPT_CD | RKEY | RVALUE |
|---|---|---|
| 내부 | 정규충족 / 정규미충족 | 50 / 0 |
| 내부 | 응급충족 / 응급미충족 | 10 / 0 |
| 외부수탁 | 정규충족 / 정규미충족 | 50 / 0 |
| 외부수탁 | 응급충족 / 응급미충족 | 30 / 0 |

→ TAT 지표 = **충족 건수 ÷ (충족+미충족) × 100(%)**, 축은 `내부/외부수탁 × 정규/응급`.
목표시간(분) 기준값은 화면에서 확인 필요.

## 3. ⬜ 미채록 11종 — 필요한 것

각 지표마다 아래 6개만 있으면 위너넷 자동집계 설계가 끝납니다.

1. 지표명 2. 정의(산출식 문장) 3. **분자** 4. **분모** 5. 단위·상수(‰ / % / 건, ×1,000 등) 6. 주기·자료원

**요청**: 프로그램에서 `QPS > 4. 지표정의서` 아래 14개 서식을 열어 **화면 캡처**해 주시면
(또는 인쇄→PDF 저장 후 경로 알려주시면) 나머지를 같은 형식으로 즉시 채록해 문서를 완성하겠습니다.
한 번에 다 안 주셔도 됩니다 — 오는 대로 이어서 채웁니다. 우선순위는 **욕창 → 손위생 → 투약 → 신체보호대**
(위너넷 적정성평가와 겹쳐 재사용 폭이 가장 큼).

## 4. 위너넷 구현에 바로 반영할 결론

- **분모 마스터**: `TBL_QPS_CENSUS`(hospCd, 연도, 구분[총재원일수/직원수], M01~M12) — SUNWOO `T_PATIENTCNT` 구조 그대로.
- **지표 정의를 데이터로**: 산식을 코드에 박지 말고 `TBL_QPS_INDI_MST`
  (지표코드, 지표명, 정의문, 분자설명, 분모설명, 분모구분, 상수[1000/100], 단위[‰/%], 주기, 자료원)에 저장.
  → 지표정의서 화면 = 이 마스터의 편집 화면, 분기보고서 = 이 마스터 + 집계 결과의 렌더링.
- **분기 보고서는 출력물**: 낙상 실물처럼 사람이 ‰를 타이핑하는 구조를 웹으로 옮기지 않는다.
  월별 분자·분모에서 자동 산출하고, 사람은 서술(분석·개선계획)만 쓴다.
