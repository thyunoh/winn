### ★계획서의 「주제」는 **항목이 아니라 데이터다**

원본에 주제가 미리 채워져 있다(개인위생관리(1) - 복장 위생 / 급식 관련 법규 / 교차 오염의 정의 …).
***그렇다고 서식의 점검항목으로 박아 넣으면 안 된다*** — 계획은 병원이 **해마다 새로 짠다.**
항목으로 고정하면 매년 서식을 고쳐야 하고, 고치는 순간 **작년 계획서까지 같이 바뀐다**
(항목은 서식에 붙고 값은 문서에 붙기 때문이다).
⇒ 주제는 사람이 적는 칸으로 두고 **기본 24행**(12월 × 2주)만 깔아 준다.

***★가르는 기준*** : 「해마다 바뀌나?」 바뀌면 **데이터**, 안 바뀌면 **항목**.
점검표의 「손 씻기」는 안 바뀌지만 교육 계획의 「노로 바이러스의 이해」는 바뀐다.

⚠**교육 계열이지만 일지와 다르다.** 일지는 「상단 폼 + 참석자 명단」이라 상단 칸이 모자랐는데,
   계획서는 **표 하나짜리 대장**이라 지금 엔진으로 그냥 된다.

⚠**「음식물 쓰레기 관리대장」과 「감량의무 사업장 …」은 같은 계열이다**(뒤가 확장판).
   둘 다 실물이 있으니 **둘 다 만든다** — 밀라운딩 때처럼 이름만 보고 합치지 않는다.

⚠**「누계」 칸이 있지만 자동 계산이 아니다.** 작성요령에 「처리량 누계는 매월 말일 기준으로
   **합산하여 누계를 작성하고**」라고 적혀 있다 — ***사람이 적는다.***
   ⇒ 「계산이 있다 → 직접 제작」 신호에 해당하지 않는다. **글자만 담으면 된다.**
   ***자동 합계를 넣어 달라는 요구가 나오면 그때 개별 화면으로 옮긴다.***

### ★식기 세척기 점검 일지가 **정규화 고침의 실증 사례**다

열이 여덟인데 **「헹굼온도(℃)」 하나만 숫자**고 나머지는 O/X 표시다.
***고치기 전이었다면 헹굼온도 「1」이 「O」로 바뀌었다.*** 오류도 안 나고 티도 안 난다.
2026-08-12 에 `INPUT_GB` 를 보고 CHECK 일 때만 맞추도록 고친 것이 정확히 이런 서식을 위한 것이다.
⇒ **시드를 만들 때 「헹굼온도」는 반드시 `NUM` 으로 넣는다.**

⚠**「밀라운딩 일지」는 원본이 행마다 머리글을 다시 찍는다**(호실·이름·내용·조치사항 블록 6개).
   ***자료로는 한 표에 6행이다*** — 머리글 반복은 종이에서 칸을 크게 쓰려는 인쇄 편의일 뿐이다.
   `LIST` 한 표로 담고, 필요하면 인쇄에서만 나눈다(반달 접기와 같은 발상).

### ★원본의 **3단** 행 머리글은 **2단으로 눌러서** 담는다

「조리실 냉장/냉동고 온도 및 위생 관리일지」의 왼쪽은 세 겹이다 :
`냉장고` → `온도` → `9am / 12pm / 5pm`. 우리 행 그룹은 **두 겹**(묶음 + 항목)이다.

***그런데 자료는 똑같이 담긴다*** — 항목명을 「온도 9am」·「온도 12pm」·「온도 5pm」·「청결도」·
「유통기한 준수」로 두고 묶음을 `냉장고`/`냉동고` 로 주면 된다.
⇒ **3단 축을 새로 만들 것 없다.** 다른 것은 **그리는 모양**뿐이고, 그건 이미 올려 둔
   「행 그룹 모양」 결정 사항과 같은 줄기다(약국 판정표 5-② 참조).

⚠***대신 항목 문구를 원본에서 벗어나게 지어내면 안 된다.*** 「온도 9am」은 원본의
   `온도` + `9am` 을 이어 붙인 것이라 괜찮지만, 없는 말을 보태는 순간 원본이 아니게 된다.

### ★「일」이 열 안에 있으면 `LIST` 다 — `ITEM_DAY` 가 아니다

**개인위생 확인 기록지**에는 `일` 이라는 열이 있다. 날짜가 있으니 `*_DAY` 로 보이기 쉽지만 아니다.
***날짜가 축이 아니라 데이터다*** — 하루에 여러 사람이, 한 사람이 여러 번 들어갈 수 있다.
`ITEM_DAY` 로 만들면 **하루에 한 줄**로 갇혀 실제 쓰임과 어긋난다.

⇒ **가르는 기준** : 「그 날짜 칸이 **미리 1~31로 깔려 있나**(축) / **사람이 적어 넣나**(데이터)」.
   깔려 있으면 날짜 격자, 적어 넣으면 대장이다.

값이 「양호: O, 불량: X」라 ***정규화와 그대로 맞는다*** — 약국의 「유/무」처럼 뒤집어 해석할 것이 없다.

### ★행 그룹이 **4종**이 됐다 — v2 에서 만들기를 잘했다

카트및엘리베이터 청소소독 · 약제과 환경 점검표 · 백신 보관 냉장고 체크리스트 ·
**일일 위생점검표**(개인위생/냉장보관/상온보관/조리작업/배식/장비/내부조리/분리/폐기물/방충구서/안전 — **11묶음**).
***일일 위생점검표는 묶음이 11개, 항목이 29개다.*** 묶음이 없으면 29줄이 그냥 늘어서서 못 읽는다.

## 1-1. ⚠새로 드러난 구멍 — **항목에 설명 열이 하나 더 필요하다**

**청소계획표**의 표 머리글은 `구분 | 청소대상 | 청소방법 | 1~31일` 이다.
`구분`은 행 그룹(`GRP_NM`)이 맡고 `1~31일`은 축이 맡는데, ***`청소대상`과 `청소방법`이 둘 다 항목 쪽이다.***

| 우리가 가진 항목 칸 | 뜻 | 여기 쓸 수 있나 |
|---|---|---|
| `ITEM_NM` | 항목 문구 | 청소대상 ✅ |
| `GRP_NM` | 묶음 | 이미 `구분`이 쓴다 ❌ |
| `UNIT_NM` | 숫자 칸 단위(℃·%) | 뜻이 다르다 ❌ |

⇒ **항목의 「설명 열」**이 없다. `ITEM_DESC` 같은 칸 하나면 풀린다(항목 표에 열 하나, 격자 머리글에 열 하나).

***판단 : 아직 만들지 않는다 — 지금 1종이다.*** 세어 두고 3종에서 만든다.
- ⚠**단, 우겨넣지 말 것.** 청소방법을 `ITEM_NM` 에 붙여 「조리대 주변 — 양념통과 정리정돈」처럼 한 줄로 만들면
  ***추출 CSV 에서 청소대상과 청소방법이 한 칸에 붙어 나온다.*** 「항목별로 세기」가 안 된다.
  넣으려면 칸을 나눠야 하고, 그때까지는 **개별 등록을 미룬다.**

## 1-2. ★★★새 축 — **주 단위 격자** · **3종 = 기준 도달. 만든다**

| 서식 | 모양 | 문서 단위 |
|---|---|---|
| 식중독 예방 위생 점검 일지 | **항목 행 × `월화수목금토일` 열** | 점검일자 **범위**(08-12 ~ 08-18) |
| 냉장고/냉동고/주방 온도·습도관리 기록지 | **요일 행 × 항목 열** (요일마다 10시/15시 2행) | 주 1장 |
| **온도 관리 기록지 (냉장고·냉동고·식품창고)** | **요일 행 × 항목 열** (요일마다 AM09:00/PM17:00 2행) | **1주차~5주차 탭** |

***→ 3종이다. 「3종 이상이면 축 추가」 기준을 넘었다.***

### 만들 때 정할 것

**① 방향이 둘이다** — `ITEM_WEEK`(항목 행 × 요일 열)와 `WEEK_ITEM`(요일 행 × 항목 열).
   `ITEM_DAY`↔`DAY_ITEM` 과 똑같은 짝이라 ***둘을 같이 만들어야 한다.*** 하나만 만들면 반쪽이다.

**② 「요일마다 2회」가 둘 다에서 나온다** (10시/15시 · AM09:00/PM17:00).
   ⇒ 행이 `요일 × 확인시간` 이다. ***이건 이미 만든 행 그룹으로 풀린다*** —
   요일이 묶음, 확인시간이 그 안의 행. **새로 만들 것이 아니다.**

**③ 문서 단위가 서식마다 다르게 표현된다** — 날짜 범위 / 주 1장 / **1~5주차 탭**.
   ***가장 단순한 것은 「연 + 월 + 주차(1~5)」다.*** 세 표현을 다 담을 수 있고
   작성 목록도 「8월 3주차」로 읽힌다.
   ⚠**`TBL_QPS_CHK_DOC` 에 주차 칸이 없다** — `IN_YEAR`+`IN_MM` 뿐이다. **DDL 한 칸이 필요하다.**

**④ 열 묶음이 3단인 것이 있다** (`온도(℃)` → `식품저장용` → `냉장고1`).
   ***2단으로 눌러 담는다*** — 항목명을 「식품저장용 냉장고1」로 두고 묶음을 `온도(℃)` 로.
   조리실 냉장/냉동고 일지에서 3단 행 머리글을 2단으로 누른 것과 같은 방법이다.

***★방향이 서로 반대다*** — `ITEM_DAY`↔`DAY_ITEM` 과 똑같은 짝이다.
축을 만든다면 **`ITEM_WEEK` / `WEEK_ITEM` 둘을 같이** 만들어야 한다(하나만 만들면 반쪽이다).

| 우리 축 | 왜 안 맞나 |
|---|---|
| `ITEM_DAY` · `DAY_ITEM` | 열(행)이 1~31일이다. 7칸이 아니다 |
| `ITEM_MONTH` | 1~12월이다 |
| `LIST` | 날짜 축이 없다 |

행 그룹은 둘 다 이미 되고(식중독=위생환경관리/개인위생/식재료보관관리/직원식당,
온도습도=온도/습도 열 묶음), 막히는 것은 **축과 문서 단위**뿐이다.

***판단 : 아직 만들지 않는다 — 2종이다.*** 세어 두고 3종에서 만든다.
- ⚠**「주」는 「일」의 변형이 아니다.** 문서 단위가 연·월이 아니라 **주**라
  작성 목록·추출·「그 달의 날 수」 계산이 전부 영향을 받는다.
  ***축 하나 더 붙이는 일로 끝나지 않는다*** — 그래서 종수가 모일 때까지 미룬다.
- ***★그런데 영양에서만 벌써 2종이다.*** 시설·간호에서 1종만 더 나오면 만든다.
  개인적으로는 **더 나올 것 같다** — 주간 점검은 흔한 주기다.
- ⚠**「주」는 「일」의 변형이 아니다.** 문서 단위가 연·월이 아니라 **주**라
  작성 목록·추출이 전부 영향을 받는다(약국의 「일 단위 문서」와 같은 종류의 문제다).
  ***축 하나 더 붙이는 일로 끝나지 않는다*** — 그래서 종수가 모일 때까지 미룬다.
- 하단의 **식중독 지수 표**(85이상 / 50~85 / 35~50 / 35미만 × 설명 × 조치사항)는
  글자가 아니라 **표**다. ※문구로는 못 담는다. 이것도 개별 화면 쪽 신호다.

  탭은 원래 화면이 갈려 있었으니 나눠도 됐지만, 여기는 다르다.

|---|---|

***★「회의록은 단일 서식으로 간다」고 확정해 둔 것이 2차 전체에서 계속 값을 돌려준다.***

⇒ **위원회 회의록은 「개별 화면 후보」에서 아예 빼도 된다.** 세지 말고 코드만 더한다.

## 2-1. ★★교육 일지 계열이 뭉친다 — ***화면 하나로 흡수할 수 있다***

부서를 넘나들며 같은 모양이 계속 나온다 :

| 서식 | 부서 |
|---|---|
| 조리원 위생교육일지 | 영양 |
| 안전교육일지 · 위생교육일지 · 위생교육계획서 | 영양 (목록에 있음) |
| 약물 교육 일지 · 직원 교육 결과 보고서 | 약국 |

***구조가 같다*** : 결재란 · 교육일시 · 장소 · 교육주제 · 교육실시자 · 참석자(명 수) ·
**교육 내용(긴 서술)** · **사진** · 참석자/참여위원 **서명 명단**.

⇒ ***사고 유형별 보고서를 유형 하나로 흡수한 것과 같은 발상이 그대로 쓰인다.***
   화면 하나 + 「교육구분」 코드면 6종이 덮인다. 점검표 엔진과는 다른 물건이지만
   **개별 화면 6개를 만드는 것보다 압도적으로 싸다.**

### ★★그런데 **안전 교육 일지**를 보니 — 교육 일지는 ***`LIST` 로도 된다***

「안전 교육 일지」는 사진도 서술도 없다. 있는 것은 두 덩이뿐이다 :

| 부분 | 내용 | 엔진에 |
|---|---|---|
| 상단 폼 | 작성일자 · 작성자 · 교육인원 · 교육내용 · 교육실시자 · 교육장소 · 특이사항 (**7칸**) | 상단 자유칸 — ***4칸뿐이라 막힌다*** |
| 하단 표 | 소속 · 연번 · 성명 · 비고 (자유행) | **`LIST` 그대로 된다** |

***막는 것이 표가 아니라 상단 칸이다.*** 약국에서 이미 네 번 본 그 병목이다.

⇒ ***`HEAD5~HEAD8` 을 늘리면 교육 일지 중 단순한 것들이 엔진으로 들어온다.***
   교육 계열 7종 전부는 아니다(조리원 위생교육일지는 사진 2쪽과 긴 서술이 있어 개별 화면이다).
   그러나 ***「교육 화면을 따로 만들까」와 「상단 칸만 늘릴까」는 크기가 완전히 다르다.***

**⇒ 상단 자유칸 확장의 값이 커졌다.** 처음엔 「점검표 4종을 구제한다」였는데,
   이제 **교육 일지 계열까지 딸려 온다.**

### ★★★확정 — **「위생 교육 일지」가 「안전 교육 일지」와 글자 하나 다르지 않다**

제목만 다르고 **상단 7칸도 하단 표도 완전히 같다.**
***이것이 「사고 유형별 보고서」와 정확히 같은 모양이다*** — 유형만 갈리고 틀은 하나다.

⇒ 결론이 둘 다 성립하고, **둘 다 값이 있다** :
1. **`HEAD5~HEAD8` 을 늘린다** → 교육 일지가 **서식 등록만으로** 들어온다. 화면을 안 만든다.
2. 사진·서술이 있는 것(조리원 위생교육일지)만 개별 화면으로 남는다.

***★★상단 자유칸 부족이 이제 6종이다*** (회수확인서 · 지참약 의뢰서 · Allergy 내역 ·
냉장고온도관리기록지 · 안전 교육 일지 · 위생 교육 일지). 기준(3종)의 두 배다.
⇒ **더 세지 않는다. 늘리는 것이 맞다.**

⚠**그런데 이건 범위 질문이 먼저다.** 교육 문서를 2차 범위에 넣을 것인가?
   ***넣는다면 6종이 화면 하나다. 안 넣는다면 6종 전부 안 만든다.*** 중간은 없다 —
   일부만 만들면 「왜 이건 있고 저건 없나」가 된다.

## 3. 원본 정리 — ***「이름이 비슷하다」와 「같은 서식이다」는 다르다***

### ①「밀라운딩일지」 vs 「밀라운딩 일지」 — **다른 서식이다** (2026-08-12 정정)

***처음에 「띄어쓰기만 다른 중복」이라고 적었으나 실물을 보니 아니었다.*** 열어 보기 전에 판단한 탓이다.

| | 밀라운딩**일지** | 밀라운딩 일지 |
|---|---|---|
| 주기 | **연**단위 | **일**단위(연·월·일) |
| 상단 | 담당자 | **점검사항 3개 × 양호/보통/나쁨** (급식 서비스 / 음식·식기 위상 / 식사의 질) |
| 표 | 상담일자·이름·식이·내용·조치사항 | 호실·이름·내용·조치사항 |
| 하단 | ※참조 사항 4줄 | — |

⇒ **둘 다 만든다.** 하나로 합치면 한쪽 자료가 갈 곳이 없어진다.

***★교훈 : 이름만 보고 중복이라고 적지 말 것.*** 반대 실수(다른 것을 같다고 묶는 것)가
빠뜨리는 것보다 나쁘다 — 빠뜨린 것은 나중에 드러나지만, 잘못 합친 것은 **드러나지 않는다.**

### ② 개인위생 계열 2종 — ***이쪽은 진짜로 겹쳐 보인다***

| | 개인위생**확인기록지** | 개인위생**점검일지** |
|---|---|---|
| 열 | 순번·일·이름 / 감염성질병유무 / 위생복·위생모·위생화 / 손상처·손톱상태·장신구착용 / 개선조치 / 확인자서명 | 일자(요일)·조리원성명 / **체온(℃)**·감염성여부 / 위생복·위생모·위생화·장신구착용·손상처·손톱상태 / 개선조치 / 확인란 |
| 다른 점 | — | **체온 칸이 있다** · 묶음 나누기가 다르다 |

***하는 일이 같다*** — 조리원 개인위생을 날마다 확인한다. 다른 것은 체온 칸 하나와 묶음 경계뿐이다.
⇒ **어느 쪽을 쓰는지 확인하고 하나만 만든다.** 둘 다 만들면 병원이 어디에 적을지 헷갈린다.
   ***이것도 확인 전에는 단정하지 않는다*** — ①에서 겪은 대로다.
