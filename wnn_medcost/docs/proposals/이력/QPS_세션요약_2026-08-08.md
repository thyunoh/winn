## ★★확정 3건 (사용자 지시 2026-08-11) — 바꾸기 전에 먼저 볼 것

**① 서식 관리는 위너넷 전용이다.**
> "서식이 너무 많은데 사용자는 못 만들고 개발자 단위 템플릿이 필요할 것 같습니다"

축을 고르고 항목을 짜는 것은 병원 담당자 일이 아니다. 사이드바에서 감추고 **컨트롤러에서도 막는다**
(`isWnn()` — 주소를 직접 쳐도 병원 계정은 작성 화면으로 보낸다). 조회·저장 API 도 같이 막았다.

**② 병원마다 양식이 다른 것은 3단으로 푼다.**
> "병원마다 양식이 틀릴텐데"

양식 차이를 뜯어 보면 **다른 것은 거의 「항목 문구」뿐**이다. 축·부가칸 구조는 병원이 달라도 같고,
점검 대상 기기 목록은 이미 서식이 아니라 **문서**에 붙어 있다.
| 단 | 무엇 | 언제 생기나 |
|---|---|---|
| 1 | 표준 서식 `HOSP_CD='*'` | 위너넷이 한 번 |
| 2 | 병원 전용 사본 `HOSP_CD=병원` | ***다를 때만*** — 복제 후 항목만 손봄 |
| 3 | 병원별 사용 목록 `TBL_QPS_CHK_USE` | 그 병원이 쓰는 것만 켬 |
- 조회 SQL 이 **병원 행이 있으면 그것, 없으면 '\*'** 로 고른다 — **지표정의서와 같은 검증된 패턴**.
- ***★사용 지정이 하나도 없는 병원은 전부 보인다(기본 열림).*** 안 그러면 새 병원이 아무것도 못 본다.
- ***이 장치 하나로 「정신 폴더 on/off」 요구도 함께 풀린다.***

**③ 부서(DEPT_CD)와 분류(CATE_CD)는 다른 축이다 — 섞지 않는다.**
> "간호/병동, 약국, 영양실, 시설 비슷할 듯합니다"

2차 네 모듈이 전부 점검표라 한 엔진에 들어간다. 그러면 서식이 한 통에 섞이므로 부서로 가른다.
`CATE` = 무엇을 점검하나 / `DEPT` = 누가 쓰나.
***같은 「냉장고 온도 점검표」가 병동·약국·영양실에 다 있다*** — 부서가 없으면 구분이 안 된다.

## ★★확정 ④ — 데이터 추출이 되어야 한다 (2026-08-11)

> "서식 생성시 주의사항은 데이터 추출 가능이어야 함"

***그림처럼 만들면 뽑을 수 없다.*** 점검표를 전산화하는 이유가 여기 있다. 두 가지를 넣었다.

**㈎ 값 정규화(`normChk`)** — ***이게 없으면 셀 수가 없다.***
사람은 같은 뜻을 제각각 적는다 — `O·○·ㅇ·o·V·v·1·Y` 가 전부 「양호」다. 그대로 담으면
「이 달 부적합 몇 건」이 안 나온다. ⇒ 담을 때 **O / X** 두 글자로 맞춘다.
- ⚠**한 글자짜리 표시만** 바꾼다. 글자·숫자 칸은 손대지 않는다 —
  「V」라는 이름도 있을 수 있고 **온도 1 을 O 로 바꾸면 자료가 망가진다.**
- `△` 같은 제3의 표시는 그대로 둔다.

**㈏ 평면 추출(`selectChkExtract`)** — 격자를 **한 줄씩** 편다.
`서식 · 부서 · 연 · 월 · 병동 · 항목 · 묶음 · 단위 · 일 · 값`
- ***★축 되돌리기는 SQL 이 한다.*** `DAY_ITEM` 은 행·열이 반대라 그대로 뽑으면 일자와 항목이 뒤바뀐다.
  화면마다 따로 풀면 **뽑는 곳마다 뜻이 갈린다.**
- `EQUIP_DAY` 는 항목명 대신 **그 문서의 기기명**을 붙인다(기기는 문서에 있다).
- 예약 900 은 `점검자` 로 이름 붙인다.
- 함께 나오는 **이행 요약**(O/X/기타 건수)이 병원이 실제로 알고 싶은 「빠짐없이 했는가」다.
- 화면 : [점검표 작성 ▸ 📊 데이터 추출] → CSV. ***BOM 을 붙인다*** — 없으면 엑셀이 한글을 깬다.
- 서식 관리 화면 상단에 **작성 주의 3줄**을 박아 뒀다(한 칸에 한 가지 · 입력종류 맞추기 · 문구는 원본대로).

**검증(2026-08-11)** — 가짜 병원 `99999998` 로 세 축(ITEM_DAY·DAY_ITEM·EQUIP_DAY)에 값을 넣고 추출했다.
`DAY_ITEM` 이 행·열이 바뀐 채 저장돼도 **일자·항목이 제자리로** 나오고, `EQUIP_DAY` 는 기기명이 붙었다. 뒷정리 확인.

`환자안전사고보고서(정신)` · `환자안전사건 개선활동 보고서` · `격리강박 시행일지` ·
`격리·강박 기록지` ×2 · `방문객 안전사고보고서`.

***정신 버전 환자안전사고보고서는 일반 버전의 「변형」이다*** — 골격은 같고 항목 세트만 다르다.

   ★단, **정신과를 운영하지 않는 병원에는 이 세트가 필요 없다** — 병원별로 켜고 끌 수 있어야 한다.
   격리·강박 3종(시행일지·기록지 2종)은 정신과 고유라 별도 서식이 필요하다.
   방문객 안전사고보고서는 대상이 **환자가 아니라 방문객**이라 환자검색을 쓰지 않는다.

**정신 ▸ 환자안전사건 개선활동 보고서** (캡처 확인) — 서식 중 가장 단순하다. 1 Page.

   보고서 폴더 전체를 이 3열표 골격 + 항목 유형(체크·수량·한줄·서술·날짜) 조합으로 짜면
   ***정신·일반·부서별 변형이 전부 데이터로 흡수된다*** — 화면은 하나면 된다.

**정신 ▸ 격리강박 시행일지** (캡처 확인) — ***보고서가 아니라 「대장(臺帳)」이다.*** 연/월 단위 다행 그리드.

→ ***감염병환자 월별 리스트(qpsInfPat)와 같은 형태.*** 그 화면을 본떠 만들면 된다.

**정신 ▸ 격리·강박 기록지 ×2 — 이름만 같고 실제로 다른 서식이다.**
- **(A) 4 Page 짜리 — 환자 1인 1건의 본 기록지**

  ★***「시행·해제·제한의 종류」 3칸 블록이 1p 안에서 3회 반복*** — 한 건에 연장·재시행이 여러 번 붙는다.
  2~4p : **격리·강박 모니터링 그리드**(시간 / 대·소변 / 음료 / 혈액순환(피부색) / V/S BP,P,BT,R /

- **(B) 1 Page 짜리 — 모니터링만 있는 속지**
  헤더가 등록번호·성명·**성별·나이**로 다르고, 컬럼이 「상태 및 INJECTION**, ROM**」으로 **ROM이 추가**됐다.

### ★「환자만족도 조사」폴더 — 폴더가 아니라 ***하나의 완결된 활동 사이클***

하위가 **6단계**로 나뉜다(각 단계가 다시 서식을 품는다) :
`안내문` → `조사 계획서` → `설문지` → `조사결과 보고서` → `지표분석 보고서` → `개선활동결과보고서`

***이건 QI 활동의 PDCA 그 자체다.*** 앞서 만든 **감염 종합보고(P/D/E 구분)** 와 같은 구조이고,
단계 수만 6개로 늘어난 것. → **하나의 화면 + 단계 구분(GB)** 으로 흡수 가능성이 높다.

- **만족도 조사안내** (캡처) — 내용이 거의 없다. 장식 테두리 + 제목 + **자유입력 박스 1개**. 게시용 안내문.
- **만족도 조사 계획서** (캡처) — 결재란 + 제출일 +
  주제 / 주제 선정 배경 / 조사팀 구성 / 조사계획(구분) / 조사기간(from~to) / 조사대상 /
  조사 인원 계획 / 조사 항목(서술) /
  **추진계획 및 활동일정** = □추진 계획(서술) + □활동 일정 **체크형 간트표**
  (행 9 : 조사 계획·설문지 작성·설문조사·설문지 통계분석·설문지 결과보고서 작성·
   개선활동 계획·개선활동 시행·개선활동 결과 분석 / 열 8 : 월)
  ★***이 간트표는 이미 구현한 「연간 활동계획서」와 같은 구조다*** — 행 정의만 바꾸면 재사용된다.

- **만족도 설문지** (캡처, 2 Page) — ***이 폴더의 핵심이자 유일하게 무거운 서식.***
  상단 안내문 문단(고정 문구) → 응답자 정보 → **5점 리커트 척도 문항표** → 기타의견.
  - 응답자 : 작성자(□환자본인 □보호자) / 성별(□남 □여) /
    연령대(□20대 □30대 □40대 □50대 □60대 □70대이상)
  - 척도 : **매우만족 5점 / 만족 4점 / 보통 3점 / 불만족 2점 / 매우불만족 1점** (모든 문항 공통)
    ★체크박스 옆 숫자는 1~5로 **왼쪽부터** 붙어 있으나 배점은 **5→1** 이다. 표시번호≠점수, 주의.
  - 영역 4개 / 문항 20개
    1. 전반적인 환경 시설 (5) — 병실내부 편의시설 · 안전시설 · 환기/냉난방 · 환자복 및 침구 교환 · 주차시설
    2. 직원의 친절성과 성의 (5) — 담당의사 · 담당간호사 · 방사선사 · 물리치료사 · 원무과직원
    3. 환자에 대한 관심과 서비스 (8) — 입원수속 절차 · 입원 대기시간 · 입원생활안내 및 낙상예방
       설명 · 치료 필요성·결과·주의사항 설명 · 의사의 질문 응답 · 투약 설명 · 식사(맛·양·질·제공시간) ·
       간병서비스
    4. 병원 의료에 대한 전반적인 만족도 (2) — 서비스 전반 만족 · 지인 권유 의향
  - 하단 **[ 기타의견 및 건의사항 ]** 서술칸

  ★***설계 요점 — 이 서식만 저장 단위가 다르다.***
  다른 서식은 「병원 1건」이지만 설문지는 ***응답자 1인 = 1건***이라 한 조사에 수십~수백 건이 쌓인다.
  → `TBL_QPS_SURVEY`(조사 회차) + `TBL_QPS_SURVEY_ANS`(응답 1건) + `TBL_QPS_SURVEY_ITEM`(문항별 점수)
  로 나눠야 하고, ***문항은 기본항목표(DEF)로 데이터화***한다(감염 우선순위 31항목과 같은 방식).
  그래야 다음 단계인 **조사결과 보고서 / 지표분석 보고서**가 이 표를 집계해서 자동으로 나온다.

- **만족도 조사결과 보고서** (캡처, **12 Page**) — ***이 폴더의 출력물 본체.
  사람이 채우는 서식이 아니라, 설문지 응답을 집계해 「자동으로 그려지는」 보고서다.***
  - **1p 표지** : `2026 년도` / `입원환자 의료서비스 만족도 조사 결과 보고서` (제목만)
  - **2p** 결재란 4칸 + [조사의 목적] [조사의 목표](서술) +
    **[조사개요]** 조사기간(from~to) · 조사대상 및 인원 · 조사방법 · 조사요원 · 통계방법 +
    **[만족지수 산출기준]** 표 —
    | 문항 | 매우만족 **1** | 만족 **2** | 보통 **3** | 불만족 **4** | 매우불만족 **5** |
    | 정의 | **5점** | **4점** | **3점** | **2점** | **1점** |
    ★***앞서 설문지에서 지적한 「표시번호 ≠ 배점」이 여기서 공식 산출기준으로 확인됐다.***
    보기 번호는 1→5, 배점은 5→1. **구현 시 반드시 뒤집어 계산**할 것.
  - **3p** [조사의 내용] `구분 | 관련 문항` 표 + [조사의 활용](서술) +
    **[만족도 조사 결과] Ⅰ.성별** — `구분(남성/여성/합계) | 빈도(명) | 비율(%)` 표 **＋ 막대그래프**
  - **4p** **Ⅱ.연령** (20·30·40·50·60·70대이상 + 합계) 표+그래프 /
    **Ⅲ.전반적인 환경 시설에 대한 만족도** 부터 ***문항별 집계 블록*** 시작
  - **4~9p** 문항별 집계 블록이 **20개 반복**. 한 블록 =
    `구분(매우만족~매우불만족) | 빈도(명) | 비율(%)` + 마지막 행 **`만족도`(가중평균)** ＋ 막대그래프.
    영역 : Ⅲ.환경 시설 → **Ⅳ.직원의 친절성과 성의** → **Ⅴ.환자에 대한 관심과 서비스** →
    **Ⅵ.전반적인 만족도** (설문지의 4개 영역과 1:1 대응)
  - **10~11p** 여백면 / **12p** `□ 의료서비스 만족도 조사 개선사항` — 3열 표(자유기재)

  ★***설계 요점***
  1. 사람이 입력하는 칸은 **2p(목적·목표·개요)·3p(조사의 내용·활용)·12p(개선사항)** 뿐.
     ***나머지 9면은 전부 설문 응답의 집계 결과다*** → 저장할 게 아니라 **조회 시 계산**해야 한다.
  2. 응답 0건이면 원본은 비율에 **`NAN`** 을 그대로 출력한다(캡처 확인). 우리는 **`-`** 로 표시할 것.
  3. 문항별 블록 20개 = **설문지 문항표(DEF)를 그대로 순회**하면 나온다. 화면에 20번 하드코딩 금지.
  4. 그래프는 가로 막대 5개. **Chart 라이브러리 없이 CSS 막대**로 충분하다(인쇄 안정성).

- **만족도 지표분석 보고서** (캡처, **10 Page**) — ★형제 서식 **`만족도 지표분석 보고서(점수)`** 가 하나 더 있음(미확인).
  ***조사결과 보고서와 집계 내용은 똑같다. 다른 건 그 집계를 「지표」 프레임에 얹었다는 것.***
  → ***이미 구현한 QPS 지표관리 서식(지표정의·분자·분모·목표·모니터링)과 같은 골격***이다.
  - **1p** 결재란 + 제출일 + **지표명** +
    **[지표정의]** 지표정의 / 분자정의 / 분모정의  ← **우리 지표 서식과 동일**
    **[목표]** `의료서비스만족도 ___ 이상`
    **[모니터링]** 지표관리자 · 모니터링 주기 · 자료수집 · 통계기법과 도구 · 기간(from~to)
    **[현황]** `년 | 평균` → 의료서비스만족도 평균점수 `00.0 %`
    **[지표 분석]** ***4개 영역 평균점수 요약표*** — `환경및시설 | 친절성 | 서비스 | 의료만족` 각 `00.0 %`
      ★***조사결과 보고서에는 없던 표.*** 지표분석 보고서만의 한 줄 요약이다.
    이어서 `1) 성별` · `2) 연령` 빈도/비율 표 + 그래프
  - **2~8p** 영역별 문항 집계 — `1.환경 및 시설` → `2.친절성` → `3.서비스` → `4.의료 만족도`.
    블록 모양은 조사결과 보고서와 **완전히 동일**(빈도/비율/만족도 + 가로막대).
    ★단 비율이 `NAN`이 아니라 **`0.0`** 으로 나온다 — 같은 데이터인데 서식마다 표기가 다르다.
  - **8p 하단** `개선 전략 및 실행` (세로 라벨 + 서술칸)
  - **9p** `결론 및 제언` / `증진활동 평가 및 추후 활동계획` (서술 2칸)
  - **10p** `□ 의료서비스 만족도 조사 개선사항` — **4열** `구 분 | 문제점 | 처리결과 | **사진**`
    ★***「사진」 컬럼 = 이미지 첨부가 필요한 유일한 표.*** 조사결과 보고서(12p)는 3열이라 사진이 없다.
    → 이미 만든 **qpsFileBox(공통 첨부)** 를 행 단위로 붙이거나, 행별 이미지 1장 업로드가 필요하다.

  ★***설계 결론 — 조사결과 보고서와 지표분석 보고서는 한 화면으로 합치지 말 것.***
  집계 로직(문항별 빈도·비율·만족도)은 **공용 함수 하나로 뽑아 쓰고**, 화면은 둘로 나눈다.
  같은 수치를 놓고 ①조사결과=단순 집계 나열 ②지표분석=지표 프레임+요약+개선전략 으로 목적이 다르고,
  결재라인도 따로 돌기 때문이다.

- ★★**만족도 지표분석 보고서(점수)** (캡처, 4 Page) — ***만족도 계산식의 「정답지」.***
  앞의 두 보고서는 결과만 보여주는데, ***이 서식은 중간 계산 과정을 그대로 인쇄한다.***
  헤더 : `문항 | 매우 만족(5) | 만족(4) | 보통(3) | 불만족(2) | 매우불만족(1) | 합계(점수/총점) | 백분율 | 평균`
  ★***헤더에 배점이 (5)…(1) 로 박혀 있다*** — 5→1 배점이 여기서 세 번째로 확인됨. 이제 확정.

  **문항 1개 = 3행 구조** (보기 5칸 각각에)
  | 행 | 내용 | 예 |
  |---|---|---|
  | 1행 | 응답 인원 | `0 명` |
  | 2행 | **인원 × 배점 = 점수** | `0 X 5 = 0` |
  | 3행 | 문항 내 해당 보기 비율 | `NAN %` |

  **합계(점수/총점) 칸** = 위에 **점수합**, 아래에 **총점**(분수 표기).
  **백분율 칸** = 위 `NAN %`, 아래 `NAN 점` — 두 값이 같이 나온다.
  **평균 칸** = 영역 단위로 세로 병합, 역시 `%` 와 `점` 두 값.
  맨 아래 행 **`평균(백분율)`** = 보기(5칸)별 평균 비율.
  **4p 맨 끝** : `의료 서비스 만족도 **전체 평균**   NAN %    NAN 점`

  ***→ 확정된 산식***
  ```
  점수합   = Σ( 보기별 인원 × 배점 )        // 배점 5,4,3,2,1
  총점     = 응답수 × 5                      // 만점 기준
  백분율(%) = 점수합 / 총점 × 100
  평균(점)  = 점수합 / 응답수                 // 5점 만점 환산
  영역 평균 = 그 영역 문항들의 위 값을 다시 평균
  전체 평균 = 전 문항 기준 최종 1개 값
  ```
  ★***「%」와 「점」은 같은 값의 두 표현이다*** (점 = % × 5 ÷ 100). 별도 입력값이 아니다.
  ★앞선 두 보고서의 `만족도` 칸 = 여기의 **평균(점)** 과 같은 값. **산식을 한 군데서만 구현**하면 된다.
  ★구성은 4개 영역 표 4개뿐 — **그래프·서술칸이 없다.** 순수 계산 검증용 출력물.

  → ***구현 판단 : 이 서식은 화면을 따로 만들 필요가 없다.***
  지표분석 보고서에 **「점수 상세 보기」 토글**로 붙이면 충분하다(같은 데이터, 표기만 상세).

- **개선활동결과보고서** (캡처, 4 Page) — ★형제 **4종** : `(원무)` `(원무2)` `(간호)` `(영양)`.
  한 장의 구성 : 결재란 4칸 +
  `부서명` / `주제` / `문제진술` / `현상파악 및 원인분석` / `개선 대책안` (서술) +
  세로라벨 `개선방안 적용 · Action · 개선지속` 안에 `*개선일시` +
  표 `유형 | 의료서비스만족도 문제점 | 개선활동 | **개선사진**`

  ★***4개 Page = 같은 서식의 반복이고, 「유형」 칸만 다르다.***
  | Page | 유형 |
  |---|---|
  | 1p | 병원 의료 관련 |
  | 2p | 시설 및 환경 |
  | 3p | 간병 서비스 관련 |
  | 4p | 간병 서비스 관련 (샘플 문구 있음: "검식과 환자 식사량등 파악하여 맛, 양, 질 높임") |

  → ***유형 = 설문지의 4개 영역과 대응.*** 만족도 조사에서 나온 문제 영역별로 한 장씩 쓴다.
  → 형제 `(원무)(원무2)(간호)(영양)` = ***부서별 버전***. **이미 쓰고 있는 FORM_GB(부서 구분) 패턴 그대로**다.
     별도 서식이 아니라 **한 화면 + 부서 구분**으로 흡수된다.
  → `개선사진` 컬럼 = 지표분석 보고서 10p에 이어 ***두 번째 이미지 첨부 지점***.

  ★**`(원무)` 버전 확인 결과 — 1 Page뿐이고 본판 1p와 완전히 같다.** 유형도 `병원 의료 관련`으로 동일.
  즉 ***부서 버전은 새 서식이 아니라, 본판에서 그 부서가 쓸 면만 떼어낸 것***이다.
  → **FORM_GB 흡수 확정.** 5종을 각각 만들 필요가 전혀 없다.
  ★**`(원무2)` 확인 — 유형이 `시설 및 환경`이다** (원무는 `병원 의료 관련`).
  ***즉 부서별 다건이 아니라 「부서 × 유형」 조합이다.*** 원무과가 두 영역에 대해 각각 한 장씩 쓴다.
  | 서식 | 부서 | 유형 |
  |---|---|---|
  | (원무) | 원무 | 병원 의료 관련 |
  | (원무2) | 원무 | 시설 및 환경 |
  | (간호) | 간호 | 간병 서비스 관련 |
  | (영양) | 영양 | ***비어 있음*** + 표 위에 **제목 입력줄 1개 추가** |

  ★**`(영양)`은 유형 칸이 비어 있다.** 대신 표 위에 자유 입력줄이 하나 더 있는데,
  본판 4p에서 "검식과 환자 식사량등 파악하여 맛, 양, 질 높임" 문구가 있던 바로 그 자리다.
  → ***유형은 코드값 고정이 아니다.*** 설문 4개 영역(환경·친절성·서비스·의료만족)에 딱 맞지 않는
     부서는 비워두고 자유 문구로 쓴다. **유형은 「선택 + 직접입력」 둘 다 허용**해야 한다.

  → 저장 키는 **`부서 + 유형`**. 부서 하나에 유형이 여러 개 붙을 수 있으므로
     `(HOSP_CD, 연도, 부서, 유형)` 단위로 잡으면 5종이 자연스럽게 들어간다.
     ***이름 뒤 숫자(원무2)를 연번으로 오해하면 키 설계가 틀어진다 — 숫자는 유형이 다르다는 표시일 뿐.***

## 결재선 (2026-08-09) — 2단계 완료

**결재(決裁)=승인 절차다. 요금 결제(決濟)가 아니다.** 인증 심사에 제출하려면 지표분석보고서에
결재가 찍혀 있어야 한다. 이전 시스템은 담당·팀장·부서장·이사장 4단계였다.

- **[신설] 테이블 2개 + 컬럼 1개** — [QPS_DDL_APPROVAL_2026-08-09.sql](../../sql/qps/ddl/QPS_DDL_APPROVAL_2026-08-09.sql), 운영 적용 완료.
  `TBL_QPS_APPR_LINE`(결재선 설정, `HOSP_CD='*'` 기본 4단계) · `TBL_QPS_APPR`(이력) ·
  `TBL_QPS_REPORT.CUR_STEP`(어디까지 승인됐는지).
- **★단계 수를 코드에 박지 않는다**(진행 방식 원칙 그대로). 병원 행이 있으면 그 병원 결재선을 쓰고,
  없으면 공통 4단계. 화면 [결재선 설정]에서 `담당, 승인` 처럼 적으면 2단계가 된다 — **코드 수정 없음.**
  *[함정] 단계를 줄일 때 뒤 행이 남으면 결재가 영원히 안 끝난다 → 저장은 DELETE 후 재삽입(통째 교체).*
- **상태 전이**: DRAFT →(상신) SUBMIT →(단계별 승인) … → 마지막 단계 승인 시 **CONFIRM**.
  반려는 REJECT + `CUR_STEP=0`(처음부터 다시), 아무도 승인 전이면 **상신 회수**(CANCEL)로 DRAFT 복귀.
  *승인 요청에 화면이 보낸 `stepNo` 와 서버의 `CUR_STEP+1` 을 대조한다 — 두 사람이 동시에 눌러도 순서가 안 꼬인다.*
- **★서술 잠금(중요)**: `saveReport` 가 `STATUS=VALUES(STATUS)` 로 상태를 덮어써서 **서술을 저장할 때마다
  결재 상태가 DRAFT 로 되돌아가는** 문제가 있었다 → 해당 구문 제거 + 컨트롤러에서 SUBMIT·CONFIRM 이면 저장 거부
  (화면도 저장 버튼을 잠근다). 결재자가 본 내용과 최종본이 달라지면 안 된다.
- **권한에 대하여(솔직히)**: 시스템에 병원 내 직위·역할 정보가 없다(로그인 = `s_userid`).
  그래서 v1 은 **'누가 언제 결재했는지를 남기는 전자서명'** 이다 — 종이 결재를 그대로 옮긴 것.
  결재자 지정·대결·알림은 사용자 마스터에 직위가 생긴 뒤에 붙인다. 이름은 `s_usernm` 쿠키로 찍는다.
- **✅검증(운영 DB, 가짜 병원 → 삭제 완료)**: 기본 4단계 상속 · 2단계 승인 시 SUBMIT 유지 ·
  3단계 반려 시 REJECT+0 복귀 · 재상신 후 4단계 승인 시 **CONFIRM** · 이력 9행 순서대로 ·
  병원 전용 2단계 결재선을 넣으면 그쪽이 이김.
- 화면: 지표분석 탭 하단 **[결재] 카드** — 상태 배지, 단계별 서명칸(이름·일시), 상신/회수/승인/반려, 이력표.
  반려는 사유 입력이 필수다(다음 사람이 무엇을 고칠지 알아야 한다). [결재선 설정]은 위너넷에만 보인다.

## 인쇄(A4) (2026-08-09) — 제출용 서식

지표분석 탭 [🖨 인쇄(A4)] → **2장짜리 제출 서식**. 1장 = 결재란·지표정의·월별·분기·추이, 2장 = 분석·개선계획·개선활동·작성일.

  미승인 단계는 빈칸(종이 결재와 같은 모양).
- *[함정] 인쇄 영역을 화면 컨테이너 안에 두면 안 된다* — print CSS 로 앱 껍데기를 숨길 때 같이 사라진다.
  자식만 `visibility:visible` 로 되살리는 방식은 **조상의 `display:none` 을 못 이긴다**.
  → `document.body` 직속 `#qfPrintHost` 를 만들어 그 안에 그린다.
- *[함정] 차트(ECharts)는 canvas 라 숨긴 영역에서 다시 못 그린다* → 화면 차트를 `getDataURL()` 로
  이미지로 떠서 넣는다(pixelRatio 2, 흰 배경).
- 수치는 **화면이 이미 계산한 값(lastCalc)** 을 그대로 쓴다 — 인쇄 때 다시 계산하지 않으므로
  화면과 인쇄물이 어긋날 수 없다.
- `@page A4 세로 · 여백 12mm`, 표·분석박스는 `page-break-inside:avoid` 로 잘리지 않게.
- 관찰형은 관찰이 없는 달의 분자를 '-' 로 찍는 규칙이 인쇄물에도 적용된다(화면과 동일).
- **[함정] 종이 맨 위의 '위너넷 분석·평가'는 우리 인쇄물이 아니다** — 브라우저가 붙이는 **머리글(page header)**

  (`손위생 수행률 지표분석보고서_경도요양병원(예천)_2026년 1/4 분기`)으로 바꿔 끼우고 `afterprint` 에 되돌린다.
  **덤: 'PDF로 저장' 시 이 제목이 파일명 기본값**이 된다. 날짜·주소 줄까지 없애려면 인쇄 창의
  [추가 설정] → [머리글 및 바닥글] 체크를 끄면 된다(확인창에 안내 문구를 넣어 뒀다).
- **[함정] 병원명은 배지 글자를 긁으면 안 된다** — 화면 로드 시점 값이라 병원을 바꾸고 새로고침 없이
  인쇄하면 **숫자는 선택 병원, 이름은 옛 병원**이 된다(2026-08-09 실제 발생). → `indiCalc` 응답에

- **[함정] `_alertBox/_confirmBox` 의 `icon` 은 글자를 그대로 찍는다** — `'warning'` 을 넘기면
  아이콘 자리에 **'warning' 이라는 단어**가 나온다. 이모지(⚠️❌❓🖨)로 넘겨야 한다(14곳 정리).

  **인쇄물은 동결값으로 찍고** 바닥에 "최종승인 시점에 확정된 값" 문구가 붙는다.
  동결값이 없는 기간(다른 분기·연간)은 실시간값 그대로.
- 동결 실패가 결재를 되돌리진 않는다(try-catch) — 결재가 본체, 동결은 부가 장치.
- **✅검증(운영 DB, 가짜 병원 → 삭제)**: 동결 4행(Q1+월3) 저장 → 기간 조회 정확 →
  동결값 vs 실시간값 분리 확인 → 해제 시 0행.
- ※화면(qfMonRate 등 지표분석 탭)은 계속 실시간이다 — 동결값 적용은 **인쇄물만**.
  화면까지 동결값으로 바꾸면 "왜 입력했는데 안 변하지"가 되므로 일부러 그렇게 뒀다.

## ✅ 손위생 실입력 검증 완료 (2026-08-09, 화면 = 사전 검산 100% 일치)

관찰 4건(1월 40/34·20/12, 2월 50/45, 3월 30/27) 입력 후 화면 값이 DB 검산과 전부 일치:
월별 76.7 / 90.0 / 90.0 % · **1분기 118/140 = 84.3%**(월별 평균 85.6% 아님 — 분자합÷분모합 확인) ·
상반기·연간 84.3% · 직군 간호사 87.8%·의사 60%·간호조무사 90% · 병동 A 76.7%·B 90% · 순간 4행 정상.
**→ MONITOR 유형 확정.** 격리·강박은 같은 코드경로라 화면만 한 번 열어보면 된다.

후속 표시 보정(같은 날): ①분류표 수행률이 `90%`/`87.8%` 로 섞여 찍히던 것 → 소수자리 고정(fmtRate).
②관찰이 없는 달·분기는 분자 0 이 '수행 0건'으로 읽혀 **분모와 함께 '-'** 로(사고형은 0 유지 — 사고 0건은 사실).

## ✅ 격리·강박 확인 완료 (2026-08-09)

같은 MONITOR 경로라 **지표 분리**를 중심으로 DB 실행 검증(가짜 병원 99999998, 손위생 행과 섞어 넣고 확인 후 삭제):
`INDI_CD` 로 정확히 갈림 — 격리 1분기 17/20 = **85.0%**, 강박 3/5 = **60.0%**, 손위생 행은 어느 쪽에도 안 섞임.
사이드바 링크(`?indi=ISOLATION` / `SECLUSION`)·마스터 정의(수행건수 ÷ 전체 시행 건수 ×100) 모두 정상.

**★고친 것 — '순간(moment)'은 손위생 전용이다**: 격리·강박 화면에도 WHO 5 moments 칸이 떠 있어
늘 빈 값으로 저장되고 **분류표에 `미상` 축 하나가 통째로 생겼다**. → `USE_MOMENT`(=INDI_CD가 HANDWASH)로
입력칸·목록열·분류표 축을 함께 감춤. 분모 명칭도 갈랐다 — **손위생=관찰건수 / 격리·강박=시행건수**
(마스터 DENOM_DESC '전체 시행 건수'와 일치). 입력 라벨·목록 머리글·차트 막대·경고문·검증 메시지에 일괄 반영.
